Primary extraction tool in PSOAS. Handles stencil creation,
file mapping, batch planning, parallel chunk-level extraction,
validation, and compute. Designed for heterogeneous internal
research databases (xlsx models, ER PDFs, call notes, analyst
memos).

**Design philosophy: performance before efficiency.** Zero
hardcodes — every routing and disambiguation decision made by
an LLM. The goal is a reliable albeit expensive baseline for
demo. After PMS2 proves out, selective deterministic shortcuts
can be reintroduced where the LLM is wasting money on easy
decisions — but that moderation is a separate, later effort.

**Design principle: LLMs reason, Python structures.** Every agent
gets its own tool-calling REPL (same agent loop scaffold as PTECA/Dailo).
But structural correctness — row ordering, cell ID assignment,
formula rewriting, dependency resolution, retry loops, state
tracking — is Python. No honor-system invariants. LLMs do
narrowly-scoped reasoning; Python owns control flow and data
integrity.

Single orchestrator tool call: `run_pms2(query)`. Everything below
is internal.

**Directory naming convention**: `0`-prefixed directories (e.g.
`0 Optical/`) are sector/thematic folders. Non-prefixed directories
are company folders. Mapper system prompt must note this convention.

Mapper agent walks `data/files_ingested/` for directory selection.
After `report_dirs`, Python `_walk_dirs()` does `os.walk`
then enriches each file with its original filetype by reading
`manifest.json` from `data/files_ingested/`. The Mapper *agent*
never touches the docstore; the Mapper *handler* reads the
manifest for filetype enrichment.

LengCaller reads chunks from `data/index/docstore.json` keyed
by `file_path` (relative path from `data/files_ingested/`, e.g.
`"LITE/Company/Lumentum-results-2026.md"`). LengCaller never
touches `data/files_ingested/`.

**Docstore access**: `01_Chunk.py` builds a `file_path_index.json`
mapping `{file_path: {node_ids: [...], filetype: "pdf"}}` alongside
the docstore. LengCaller uses this for O(1) file→chunks lookup
instead of scanning the full docstore. Filetype in
`file_path_index.json` is copied from `manifest.json` at chunk time.

## PMS2 Ingest (two scripts)

Ingest is split into two independent scripts. 00_Ingest converts
raw files to markdown. 01_Chunk chunks the markdown into a
docstore. Both are incremental (hash-tracked, skip unchanged).

### 00_Ingest.py — Convert raw → markdown

Reads from `data/files_raw/`, writes to `data/files_ingested/`.
Uses docling for all conversions (pdf→md, docx→md).
**Supported filetypes: `.pdf`, `.docx` only.** xlsx deferred.

1. Walk `data/files_raw/` for supported files (`.pdf`, `.docx`).
   If zero supported files found, print
   `"[Chunk_master] Raw files are empty JIT!!"` and return
   immediately (no manifest, no hashes written).
2. SHA-256 hash each raw file, compare against
   `data/files_ingested/convert_hashes.json` — skip unchanged
3. For each new/changed file:
   a. Docling convert → markdown string
   b. Write `.md` file to mirrored path in `files_ingested/`
      (e.g. `files_raw/LITE/Company/results.pdf`
       → `files_ingested/LITE/Company/results.md`)
4. Build manifest from ALL supported raw files found in step 1
   (not just converted ones). For each raw file, compute the
   corresponding .md relative path and map it to the original
   extension. This ensures the manifest is always complete even
   when step 2 skips unchanged files.
   Write `data/files_ingested/manifest.json` (full rebuild every run).
5. Write `data/files_ingested/convert_hashes.json`

**manifest.json format:**
```json
{
    "LITE/Company/Lumentum-results-2026.md": "pdf",
    "LITE/Notes/RICHARD HO.md": "docx",
    "0 Optical/Reports/Mizuho_LITE.md": "pdf"
}
```

Key = relative path within `files_ingested/` (matches `file_path`
metadata on chunks). Value = original source file extension
(without dot). 01_Chunk reads this to stamp `filetype` on chunks.

**Docling usage:**
```python
from docling.document_converter import DocumentConverter

converter = DocumentConverter()
result = converter.convert(abs_path)
md_text = result.document.export_to_markdown()
```

### 01_Chunk.py — Chunk markdown → docstore

Reads from `data/files_ingested/`, writes to `data/index/`.
Standalone copy of PMS1 `ingest.py` chunking pipeline with
modifications. No import dependency on PMS1 — fully decoupled.

**Hard dependency on `manifest.json`**: 01_Chunk crashes if
`data/files_ingested/manifest.json` does not exist. Run
00_Ingest first. No fallback to "unknown" filetype.

**Pipeline:**
1. Load all `.md` files from `files_ingested/` via `_read_md`
   (PMS1's markdown reader — splits on headers, keeps tables
   with context)
2. `_merge_stub_headers` (PMS1, unchanged)
3. `_split_tables` (PMS1, unchanged)
4. `_split_sub_tables` (PMS1, unchanged)
5. `_chunk_documents` via `SentenceSplitter` (512 tok, 0 overlap)
   — tables kept atomic. Overlap = 0; `_inject_overlap` handles
   context injection post-chunking instead.
6. `_tag_chunk_indices` — **modified from PMS1**:
   - Keep: `chunk_index`, `fiscal_year`
   - Add: `filetype` (read from `manifest.json`)
   - Drop: `dir_implied_firm`, `dir_implied_sector` (PMS2 doesn't
     use FIRM_SYNONYMS — Mapper walks dirs directly)
7. `_inject_overlap` — **new** (±1k char from neighbors, per file)
8. Serialize:
   - `SimpleDocumentStore.persist()` → `data/index/docstore.json`
     (no embeddings, no VectorStoreIndex)
   - Build `file_path_index.json` → `data/index/file_path_index.json`
     **Full rebuild every run** — scan entire docstore after
     chunking (including unchanged files' nodes). Not incremental.
     Simple and correct; chunk is a batch job, no perf concern.
   - Save hashes → `data/index/file_hashes.json`

**NOT produced** (no embeddings):
- `index_store.json`
- `*_vector_store.json`

**Incremental**: SHA-256 hash each `.md` file in `files_ingested/`,
compare against `data/index/file_hashes.json`. Only re-chunk
changed files. Delete stale nodes from docstore, insert new ones.

**Metadata conventions:**

| Field | Value | Used by |
|---|---|---|
| `file_name` | Basename only: `"Lumentum-results-2026.md"` | Display, logging |
| `file_path` | Relative to `data/files_ingested/`: `"LITE/Company/Lumentum-results-2026.md"` | LengCaller docstore queries, attribution |
| `filetype` | Original source type from manifest: `"pdf"`, `"docx"` | Batch Planner routing heuristics |

`file_path` is the primary match key. No basename collision
possible — paths are unique by definition. `file_name` retained
for human-readable logging only. `filetype` read from
`manifest.json` (written by 00_Ingest from original file extension).

### New: overlap injection

After `_chunk_documents` produces nodes, a post-chunking pass
injects ±1k char overlap from neighboring chunks of the same
file. This gives every chunk (text and table) surrounding context
without modifying the core chunking logic.

Overlap is demarcated with structural markers so downstream
consumers (Leng) can distinguish context from core content.

```python
_OVERLAP_CHARS = 1000

def _inject_overlap(nodes: list) -> list:
    """Add ±1k char overlap from neighboring chunks, per file.

    Groups nodes by file_path, sorts by chunk_index within each
    group, then prepends/appends neighbor text with demarcation
    markers.
    """
    from collections import defaultdict

    by_file = defaultdict(list)
    for node in nodes:
        fpath = node.metadata.get("file_path", "")
        by_file[fpath].append(node)

    for fpath, file_nodes in by_file.items():
        file_nodes.sort(key=lambda n: n.metadata.get("chunk_index", 0))

        # Snapshot original texts before mutation
        original_texts = [n.text for n in file_nodes]

        for i, node in enumerate(file_nodes):
            # Front overlap: up to 1k chars from preceding chunk(s)
            front = ""
            j = i - 1
            while j >= 0 and len(front) < _OVERLAP_CHARS:
                take = original_texts[j][-((_OVERLAP_CHARS) - len(front)):]
                front = take + front
                j -= 1

            # Back overlap: up to 1k chars from following chunk(s)
            back = ""
            j = i + 1
            while j < len(file_nodes) and len(back) < _OVERLAP_CHARS:
                take = original_texts[j][:_OVERLAP_CHARS - len(back)]
                back += take
                j += 1

            # Demarcate and inject
            parts = []
            if front:
                parts.append(f"--- context ---\n{front}\n--- end context ---\n")
            parts.append(node.text)
            if back:
                parts.append(f"\n--- context ---\n{back}\n--- end context ---")

            node.text = "\n".join(parts)

    return nodes
```

all three. Python normalizes to absolute downstream.

### Overlap and attribution

If Leng finds a value that physically appears in the overlap
zone, the node_id still points to this chunk. This is acceptable:
the overlap zone is intentionally included to provide context,
and the value is genuinely relevant to this chunk's content.
The demarcation markers tell Leng where the core content is —
Leng should prefer extracting from core content, but context-zone
values are not invalid.

## Architecture

```
run_pms2(query)
    |
    +-- PHASE 0: Sekei (agent loop, exits after finalize)
    |     Firms + periods from orchestrator (pre-structured).
    |     T1: ask_user(sectors, periodicity, metric disambig)
    |     T2: run_mapper(firms, notes incl sector answer)
    |     T3: ask_user -> preview stencil
    |     T4: finalize_stencil -> Python post-process (topo, cell IDs)
    |         error -> handler returns None, Sekei re-calls finalize
    |     Sekei exits. Done.
    |
    +-- PHASE 1: Dispatcher x N — per firm, parallel (Python loop)
    |     PRE-LOOP (once per firm, if granularity != "annual"):
    |       FiscalCalResolver: structured_complete(web_search=True)
    |         -> {Q1FY2025: "Jul 1 2024–Sep 30 2024", ...}
    |         -> injected into all Leng + Validator calls
    |         -> None on failure (degrade, don't crash)
    |     LOOP until complete / BP exhausted / user aborted:
    |       Prune satisfied helper cells
    |       Batch Planner (agent loop):
    |         reasons about routing, prefers hedging over ask_user
    |         on systematic unit mismatch: ask_user → override_firm_currency
    |         calls run_leng_caller(plan) OR report_exhausted
    |         LengCaller (Python) internally:
    |           chunk fetch -> Leng x N (all parallel)
    |           hits -> Validator x N (all parallel)
    |           Validator writes to job_stencil (lock)
    |           LengCaller updates searched_files
    |         returns "complete" -> BP exits -> Dispatcher
    |       Dry run safety net: N consecutive dry → force ask user
    |
    +-- PHASE 2: Merge + Compute (Python)
    |     merge job values → work stencil, formula eval on work stencil
    |     extract ans rows → ans stencil, serialize → display stencils
    |     persist work + ans to disk, job stencils discarded
    |
    +-- return summary string + opaque handle names
```

## Agent loop pattern

Every LLM role in PMS2 (except Leng) follows the same **agent
loop scaffold**. Same pattern as PTECA (`ask_user` + `finalize`)
and Dailo (`list_dir` + `spawn_gulei` + `report_results`).

**Parallel tool dispatch**: each PMS2 agent loop inlines its own
`ThreadPoolExecutor` for parallel tool calls. Does NOT reuse
`_dispatch_parallel` from `agent_loop.py` — that is hardwired
to the orchestrator's `execute_tool` dispatch table. PMS2
agents have their own tool handlers and TerminalRouter channels.

**`ask_user` serialization**: all `ask_user` calls across all
parallel agents (Mappers, Dispatchers, BPs) serialize through
the TerminalRouter's `_input_queue`. Multiple threads can call
`ch.input()` concurrently — they queue and the user answers
one at a time. No special handling needed beyond ToolChannel.

```python
# Agent loop scaffold — every agent follows this
messages = [{"role": "user", "content": initial_prompt}]
turn_counter = 0

while turn_counter < MAX_TURNS:
    response = backend.call_with_tools(
        messages=messages,
        system_prompt=sys_prompt,
        tools=AGENT_TOOLS,
    )

    # end_turn without terminal tool = error
    if response.stop_reason == "end_turn":
        messages.append(response.to_assistant_message())
        messages.append({
            "role": "user",
            "content": "Error: you must call <terminal_tool>.",
        })
        turn_counter += 1
        continue

    # Dispatch all tool calls in parallel via ThreadPoolExecutor.
    # ask_user blocks on ToolChannel queue; exploration tools
    # (e.g. run_mapper) run concurrently in separate threads.
    # Sekei calls ask_user first, run_mapper after (sequential).

    tool_results = []
    terminal_result = None

    has_ask_user = any(t.name == "ask_user" for t in response.tool_calls)
    has_explore = any(t.name in EXPLORATION_TOOLS for t in response.tool_calls)
    terminal_count = sum(1 for t in response.tool_calls if t.name in TERMINAL_TOOLS)

    def _dispatch_tc(tc):
        if tc.name == "ask_user":
            answer = ch.input(tc.input["question"])
            trace.record_user_interaction(tc.input["question"], answer)
            return tc, f"User answered: {answer}", None
        elif tc.name in TERMINAL_TOOLS:
            # Guard 1: reject if ask_user or exploration also called
            # this turn. Terminal tools exit the loop — async results
            # would be silently lost.
            if has_ask_user or has_explore:
                return tc, "Error: cannot finalize in same turn as ask_user or exploration tools.", None
            # Guard 2: reject if multiple terminal tools called
            # (e.g. run_leng_caller + report_exhausted — contradictory).
            # Non-deterministic race otherwise.
            if terminal_count > 1:
                return tc, "Error: cannot call multiple terminal tools in the same turn.", None
            else:
                # _handle_terminal returns (data, status_string).
                # data = structured result on success, None on
                # validation error (e.g. topo sort failed).
                # status_string = always present, sent to LLM as
                # tool result. On error, contains the error detail
                # so LLM can inspect and self-correct on next turn.
                data, status_string = _handle_terminal(tc.name, tc.input)
                return tc, status_string, data
        elif tc.name in EXPLORATION_TOOLS:
            result = _handle_exploration(tc)
            return tc, result, None
        return tc, "Error: unknown tool.", None

    from concurrent.futures import ThreadPoolExecutor, as_completed
    with ThreadPoolExecutor() as pool:
        futures = {pool.submit(_dispatch_tc, tc): tc for tc in response.tool_calls}
        for fut in as_completed(futures):
            tc, content, t_result = fut.result()
            tool_results.append({"id": tc.id, "name": tc.name, "content": content})
            if tc.name == "ask_user":
                turn_counter = 0  # intentional: no absolute ceiling
            if t_result is not None:
                terminal_result = t_result

    messages.append(response.to_assistant_message())
    messages.append(LLMResponse.make_tool_results_message(tool_results))

    # Terminal tool handler returns (data, status_string).
    # data is None on validation error (e.g. topo sort failed),
    # non-None on success. Loop continues on None so the agent
    # can inspect the error (in status_string, already sent as
    # tool result) and retry.
    if terminal_result is not None:
        return terminal_result

    turn_counter += 1

# Post-loop: MAX_TURNS exhausted without terminal tool succeeding.
# Return sensible default per agent:
#   Validator: [] (empty cell_outcomes — treated as miss)
#   Sekei: raise RuntimeError (stencil not finalized)
#   Mapper: raise RuntimeError (dirs not reported)
#   BP: "exhausted" (same as report_exhausted)
# Implementer must add per-agent post-loop return.
raise RuntimeError(f"Agent loop exhausted {MAX_TURNS} turns without terminal tool.")
```

Note: `TERMINAL_TOOLS` is a set. Any terminal tool exits
the loop. Validator has a single terminal tool
(`submit_verdicts`) that handles both writes and rejections
in one batch call.

**Per-agent specifics:**

| Agent | Tools | Terminal | Explore | Max turns |
|---|---|---|---|---|
| Sekei | `ask_user`, `run_mapper`, `finalize_stencil` | `finalize_stencil` | `run_mapper` | 8 |
| Mapper | `ask_user`, `list_dir`, `report_dirs` | `report_dirs` | `list_dir` | 6 |
| Batch Planner | `ask_user`, `run_leng_caller`, `report_exhausted`, `override_firm_currency` | `run_leng_caller`, `report_exhausted` | `override_firm_currency` | 4 |
| Validator | `submit_verdicts` | `submit_verdicts` | — | 2 |

Leng is the exception: single `structured_complete()` call per
chunk. No tools, no user interaction, no multi-turn. Pure
structured extraction. Uses `structured_complete()` in `llm.py`
— tool-calling shim for Anthropic (single tool call with schema
as input_schema).

**`structured_complete()` does NOT exist in `llm.py` yet — must be
added.** Base class raises `NotImplementedError`. Only
`AnthropicLLM` implements (tool-call shim). Other subclasses
left unimplemented — all PMS2 roles are Anthropic.

```python
_STRUCTURED_MAX_RETRIES = 2  # 1 retry on parse failure

def structured_complete(
    self,
    prompt: str,
    schema: dict,           # JSON schema for output
    system_prompt: str | None = None,
    label: str = "",
    web_search: bool = False,
) -> dict:
    """Return structured JSON matching schema.

    Anthropic-only (all PMS2 roles are Anthropic):
      single tool call with schema as input_schema,
      parse tool_use block. API errors (429/500/timeout)
      handled by llm.py retry logic.

    Parse failure retry: Haiku fumbles tool calls ~2% of
    the time. Retries are stochastic — same prompt usually
    succeeds on re-roll. One retry at ~$0.001 per fumble
    is cheaper than a lost chunk. Raises on final failure
    (LengCaller treats as miss).

    web_search: if True, adds provider's native web search
    tool to the API call. See web_search flag docs below.

    Base class: NotImplementedError. Only AnthropicLLM
    implements. Other subclasses left unimplemented.
    All 5 PMS2 roles are Anthropic-only for demo. No
    DeepSeek/OpenAI fallback needed.
    """
    for attempt in range(_STRUCTURED_MAX_RETRIES):
        # Build single-tool API call. Schema becomes the tool's input_schema.
        # No thinking — structured_complete is a cheap extraction call.
        tool = {
            "name": "structured_output",
            "description": "Return structured data matching schema",
            "input_schema": schema,
        }
        tools = [tool]
        if web_search:
            tools.append({"type": "web_search_20250305",
                          "name": "web_search", "max_uses": 1})
        kwargs = {
            "model": self._model,
            "max_tokens": self._max_tokens,
            "messages": [{"role": "user", "content": prompt}],
            "tools": tools,
        }
        # Force tool use when web_search is off (Leng, Validator).
        # Without this, Haiku returns text blocks instead of tool
        # calls ~14% of the time → silent data loss.
        # Can't force when web_search is on — model needs to call
        # web_search first (FiscalCalResolver).
        if not web_search:
            kwargs["tool_choice"] = {"type": "tool", "name": "structured_output"}
        if system_prompt:
            kwargs["system"] = system_prompt
        # No thinking block — even if instance has thinking enabled.
        # structured_complete is a single-shot extraction.
        resp = self._client.messages.create(**kwargs)
        # Find the tool_use block for "structured_output"
        for block in resp.content:
            if block.type == "tool_use" and block.name == "structured_output":
                # Trace recording
                from src.harness.trace import get_current_trace
                trace = get_current_trace()
                if trace:
                    trace.record_llm_call(
                        messages=[{"role": "user", "content": prompt}],
                        response=json.dumps(block.input),
                        model=self._model,
                        label=label,
                    )
                return block.input
        # No tool_use block found — parse failure, retry
        if attempt == _STRUCTURED_MAX_RETRIES - 1:
            raise ValueError(
                f"structured_complete: no tool_use block after "
                f"{_STRUCTURED_MAX_RETRIES} attempts"
            )
```

### web_search flag on LLMBackend

results inline. No MCP, no external search API, no infra.

**Provider-agnostic**: each subclass translates the flag to

never touches provider-specific tool definitions.

  ```python
  else:
  ```

## Stencil model

PMS2 uses three stencil types that flow through the pipeline:

```
  SEKEI LLM outputs raw rows
  (metric names, formulas-by-name, ans flags)
       |
       |  Python: topo sort, row numbers,
       |  Rn formulas, cell IDs, feeds_rows
       v
  WORK STENCIL (complete, correctly ordered)
       |
       |  Python: split per firm (filter, not deep copy)
       v
  JOB STENCILS (one per firm, ephemeral in-memory)
       |
       |  Dispatcher fills values via
       |  Batch Planner + LengCaller iterations
       |
       |  Phase 2: merge job values back → work stencil
       |           compute formulas on work stencil
       |           extract ans rows → ans stencil
       v
  WORK STENCIL (filled, all firms, all rows — audit artifact)
  ANS STENCIL (ans rows only — user-facing output)
  DISPLAY STENCILS (per-firm, ans rows only — downstream)
```

### Ans stencil

Contains only what the user requested. Metadata-only until
Phase 2 extracts ans values from the filled work stencil.
Uses work stencil cell IDs directly — no separate ID space,
no reconciliation.

`row_mapping` populated from work stencil rows where
`ans: true`. Saved to disk by Phase 2 after filling.

After Phase 2 fills it, `filled` is a flat `{firm: {cell_id: value}}`
map using work stencil cell IDs. Machine-readable, not meant
for direct human consumption — rendering as a display table
is a separate concern.

```json
{
    "metrics": ["Gross Margin", "EBITDA"],
    "periods": ["FY2025", "FY2026", "FY2027"],
    "firms": ["LITE", "Innolight"],
    "col_letters": ["A", "B", "C"],
    "row_mapping": {
        "LITE": {
            "Gross Margin": 5,
            "EBITDA": 6
        },
        "Innolight": {
            "Gross Margin": 11,
            "EBITDA": 12
        }
    },
    "filled": {
        "LITE": {
            "A5": 0.328,        "B5": 0.329,        "C5": null,
            "A6": 8500000000,   "B6": 9550000000,   "C6": null
        },
        "Innolight": {
            "A11": 0.41,        "B11": 0.402,       "C11": 0.398,
            "A12": 1200000000,  "B12": 1350000000,  "C12": 1400000000
        }
    }
}
```

`row_mapping` is **per-firm** — each firm's ans rows have
different row numbers (and thus different cell IDs). Bridges
cell IDs to metric names for display rendering, PTECA context.
To reconstruct a human-readable table: iterate
`row_mapping[firm]` for row labels, `col_letters`/`periods`
for column headers, `filled[firm][cell_id]` for values.

The filled ans stencil does much of what PTECA currently does —
metric pruning and period alignment are already resolved by
the user during stencil creation. PTECA runs with less work
when fed PMS2's filled ans stencil, handling only chart layout
(per-firm vs comparison, title, grouping by unit). Deferred.

### Work stencil

Expanded version with helper rows for formula dependencies.
Row-oriented structure: metadata per row, values in a flat map.

**Row ordering is determined by Python topo sort, not by the
LLM.** Ascending row number = dependency order. Guaranteed.

```
                              | A(FY25) | B(FY26) | C(FY27) | firm  | unit  | type     | feeds_rows | formula
------------------------------+---------+---------+---------+-------+-------+----------+-----------+--------

```

**Rows are firm-specific.** Each row belongs to one firm via the
`firm` field. Metric names are plain — `firm` is the disambiguator.
Formulas reference rows within the same firm's block only
(LITE GM = R2/R1, INNO GM = R8/R7). 2 firms × 6 KPIs = 12 rows.

Note: retrieve rows (depth 0) come first, compute rows
(depth 1+) after their dependencies. This is not coincidence
— it's the topo sort guarantee. Within each firm block, topo
order holds independently.

Cell ID convention: `{col_letter}{row_number}` like Excel.
Column letters = periods (A=FY25, B=FY26, C=FY27).
Row numbers = 1-indexed, assigned top-to-bottom after topo sort.

### Periods

Single shared `periods` list = union of all firms' requested
periods. e.g. query "LITE FY2026, Innolight FY2020-FY2021"
→ `periods: ["FY2020", "FY2021", "FY2026"]`. All job stencils
have the same columns. Firms that lack data for some periods
get nulls — normal gap handling. Cross-firm temporal comparison
only works when periods overlap.

### Job stencils

Per-firm **filtered subsets** of the work stencil. **Ephemeral
— in-memory only, never written to disk.** Each job stencil
contains only that firm's rows (not a deep copy of all rows).
Cell IDs are preserved from the work stencil (global ID space).
After Dispatchers complete, Phase 2 merges their values back
into the work stencil and discards them.

```
job_LITE:            firm="LITE", rows=R1-R6 only, values=A1-C6 null
job_Innolight:       firm="Innolight", rows=R7-R12 only, values=A7-C12 null
```

Cell IDs are **disjoint** across firms. Each firm owns its own
row range and cell ID range. No collision.

### Field reference

**Row fields** (per-row, period-independent):

| Field | Type | Description |
|---|---|---|
| `metric` | str | Plain metric name (e.g. `"Revenue"`, `"D&A"`). NOT globally unique — `(firm, metric)` is the unique key. |
| `firm` | str | Which firm this row belongs to. Must match a value in `firms` array. Sole disambiguator for duplicate metric names across firms. Used by `_assign_structure` to filter rows into per-firm job stencils. |
| `type` | `"retrieve"` or `"compute"` | Retrieve = extract from files. Compute = derive from formula. |
| `timeframe` | str | `"annual"`, `"quarterly"`, `"LTM"` |
| `unit` | str | `"USD"`, `"JPY"`, `"EUR"`, `"GBP"`, `"CNY"`, `"float"`. What kind of thing the value represents. Canonical Chinese currency = `"CNY"` (alias `"RMB"` normalized in Python). |
| `feeds_rows` | list[int] or absent | Row numbers this row feeds. Informational — helps Batch Planner prioritize. Assigned by Python from dependency graph. Present only for helper-only rows (not `ans: true`). Lists ALL compute rows that reference this metric. |
| `formula` | str or absent | Row-template formula. Uses `Rn` notation (e.g. `R2/R1`). Present only for `type: "compute"`. Assigned by Python (rewritten from metric-name formulas). |
| `ans` | bool or absent | `true` if this row maps back to the ans stencil (user-requested metric). Absent/false for helper-only rows. |

**Dual-purpose example**: user asks for "Revenue, Gross Margin".
Revenue is both independently requested AND feeds Gross Margin.
Revenue row: `ans: true`, no `feeds_rows`. Revenue's value is
always needed — it is never skippable.

**Helper-only example**: user asks for "Gross Margin" but NOT
Revenue. Revenue row: `feeds_rows: [5]`, no `ans`. Revenue is
only needed if Gross Margin (row 5) can't be found directly.

**Values map** (flat, cell_id -> value):

- Key: `"{col_letter}{row_number}"` e.g. `"A1"`, `"B5"`
- Value: number (absolute, denom-normalized) or null. Null = unfilled.

**Sources map** (flat, cell_id -> source string):

- Key: same as values
- Value: either a docstore node_id string (for cells where Leng
  found a value — attribution = chunk that Leng read) or
  `"formula:{Rn expression}"` (for cells computed by Phase 2,
  e.g. `"formula:R2/R1"`). Absent only for unfilled cells.

### Row-template formula notation

Formulas use `Rn` to reference row n in the same column:

```
"formula": "R2/R1"
```

At eval time for column A: `R2` -> `values["A2"]`, `R1` -> `values["A1"]`.
Same formula applies to every column. The column letter is a loop
variable — the formula is stated once per row, not per cell.

**Cross-column references** use `Rn[-k]` syntax to offset by k
columns to the left. `Rn[+k]` offsets right (forward-looking).

```
"formula": "(R1-R1[-1])/R1[-1]"     ← Revenue YoY Growth
```

At eval time for column B (FY2026): `R1` → `values["B1"]`,
`R1[-1]` → `values["A1"]` (FY2025). For column A (first period):
`R1[-1]` → no column left → null → cell skipped (can't compute
YoY for first period). Correct behavior.

**Resolution rules:**
- `Rn` = same column (offset 0). Shorthand for `Rn[0]`.
- `Rn[-k]` = k columns to the left. Out of bounds → null → skip.
- `Rn[+k]` = k columns to the right. Out of bounds → null → skip.
- Column offset is resolved by index into `col_letters` list:
  if current column is `col_letters[i]`, then `Rn[-k]` →
  `values["{col_letters[i-k]}{n}"]` if `i-k >= 0`, else null.

**Topo sort unaffected.** Dependencies are row-level (which rows
feed which). Column offsets are orthogonal — resolved at eval
time, not at sort time.

**LLM output syntax:** Sekei outputs `{MetricName}[-1]` for
cross-column refs. Python rewrites `{Revenue}` → `R1`,
preserves `[-1]` → `R1[-1]`.

**Dry-run syntax check:** regex `R\d+(\[[+-]?\d+\])?` substitutes
1.0 for all Rn and Rn[±k] refs. Same `_safe_math_eval` call.

Only arithmetic operators allowed: `+`, `-`, `*`, `/`, `(`, `)`.
Evaluated via AST-walked safe math (no `eval()`).

**Rn formulas are Python-generated.** The LLM outputs formulas
using exact metric names in `{MetricName}` syntax (e.g.
`"{Gross Profit}/{Revenue}"`, `"({Revenue}-{Revenue}[-1])/{Revenue}[-1]"`).
Python rewrites metric names to Rn after topo sort assigns row
numbers, preserves `[-k]`/`[+k]` suffixes.

### feeds_rows semantics

`feeds_rows` is **operational metadata** assigned by Python
from the dependency graph. It tells Batch Planner which helper
rows feed which compute rows. **List, not scalar** — a retrieve
row can feed multiple compute rows (e.g. Revenue feeds both
Gross Margin and Revenue Growth).

**Runtime use: helper cell pruning.** Before each Dispatcher
iteration, the Dispatcher checks each unfilled helper cell: if
ALL compute cells it feeds are already filled (Leng found the
compute values directly), the helper cell is excluded from the
active_cells list passed to Batch Planner.
Helper stays active if ANY consumer still has nulls.
Prevents wasting retry budget on cells whose downstream
consumers are already satisfied.

The formula eval logic in Phase 2 handles both cases naturally:

```
For column C, row 1 has feeds_rows=[5] (Gross Margin):
  if values["C5"] is not null:
    -> Gross Margin found directly by Leng
    -> Row 1's value may also be filled, doesn't matter
    -> formula eval skips C5 (already filled)
  else:
    -> Gross Margin needs computing from R2/R1
    -> if values["C1"] is null, formula fails -> accept gap
```

This is evaluated per column independently by `_compute_formula_cells`.

### Algorithm

Metric names are plain (e.g. `"Revenue"`, not `"LITE Revenue"`).
`(firm, metric)` is the unique key. Topo sort runs **per-firm**
independently, then concatenates results. This guarantees
within-firm dependency order and keeps formula resolution simple
(no composite keys in Kahn's).

```python
import re
from collections import defaultdict, deque


def _parse_formula_refs(formula: str) -> list[str]:
    """Extract metric names from {MetricName} or {MetricName}[-k] syntax.

    Cross-column offset is stripped — dependency is row-level.
    "{Revenue}[-1]" → "Revenue" (same row dep as "{Revenue}").
    """
    return re.findall(r"\{([^}]+)\}", formula)


def _topo_sort_firm(firm_rows: list[dict], firm: str) -> list[dict]:
    """Topological sort for one firm's rows.

    Returns rows in sorted order. Raises ValueError if cycle,
    duplicate metric names within firm, or compute row missing
    formula.
    """
    # Guard: duplicate metric names within firm
    names = [r["metric"] for r in firm_rows]
    dupes = [n for n in names if names.count(n) > 1]
    if dupes:
        raise ValueError(
            f"Duplicate metrics for {firm}: {set(dupes)}. "
            f"Each metric must be unique within a firm."
        )

    # Guard: compute row missing formula
    for row in firm_rows:
        if row["type"] == "compute" and not row.get("formula"):
            raise ValueError(
                f"Compute row '{row['metric']}' ({firm}) has no formula."
            )

    name_to_row = {r["metric"]: r for r in firm_rows}

    # Build adjacency: metric -> [metrics it depends on]
    deps: dict[str, list[str]] = {}
    for row in firm_rows:
        formula = row.get("formula", "")
        refs = _parse_formula_refs(formula) if formula else []
        # Validate all refs exist within this firm
        for ref in refs:
            if ref not in name_to_row:
                raise ValueError(
                    f"Formula for '{row['metric']}' ({firm}) "
                    f"references unknown metric '{ref}'"
                )
        deps[row["metric"]] = refs

    # Kahn's algorithm
    in_degree = {m: 0 for m in name_to_row}
    reverse_adj: dict[str, list[str]] = defaultdict(list)
    for metric, dep_list in deps.items():
        in_degree[metric] = len(dep_list)
        for d in dep_list:
            reverse_adj[d].append(metric)

    queue = deque(m for m, deg in in_degree.items() if deg == 0)
    sorted_names: list[str] = []

    while queue:
        m = queue.popleft()
        sorted_names.append(m)
        for consumer in reverse_adj[m]:
            in_degree[consumer] -= 1
            if in_degree[consumer] == 0:
                queue.append(consumer)

    if len(sorted_names) != len(firm_rows):
        raise ValueError(f"Circular dependency in {firm} formulas")

    return [name_to_row[m] for m in sorted_names]


def _topo_sort_rows(raw_rows: list[dict], firms: list[str]) -> list[dict]:
    """Topo sort all rows, per-firm independently, concatenate.

    Firm order in output follows `firms` list order.
    Within each firm, topo order guaranteed.
    """
    sorted_all = []
    for firm in firms:
        firm_rows = [r for r in raw_rows if r["firm"] == firm]
        sorted_all.extend(_topo_sort_firm(firm_rows, firm))
    return sorted_all


def _assign_structure(
    sorted_rows: list[dict],
    periods: list[str],
    firms: list[str],
) -> tuple[dict, dict, list[dict]]:
    """Assign row numbers, rewrite formulas, build stencils.

    Rows are firm-specific (each has a 'firm' field). Job stencils
    are filtered subsets of the work stencil, not deep copies.
    ans determination uses Sekei's `ans: true` tags directly —
    no separate ans_metrics set. User confirms tags during
    Turn 3 stencil preview (safety net against Sekei fumbles).

    Returns (work_stencil, ans_stencil, job_stencils).
    """
    # Guard: every row has a valid firm field
    for row in sorted_rows:
        if row.get("firm") not in firms:
            raise ValueError(
                f"Row '{row['metric']}' has firm '{row.get('firm')}' "
                f"not in firms list {firms}."
            )

    # Guard: formula refs exist within same firm (already validated
    # by _topo_sort_firm, but belt-and-suspenders)

    if len(periods) > 26:
        raise ValueError(
            f"Too many periods ({len(periods)}). Max 26 "
            f"(single-letter column IDs A-Z)."
        )
    col_letters = [chr(ord("A") + i) for i in range(len(periods))]

    # (firm, metric) -> row_number. Needed because metric names
    # are NOT globally unique — "Revenue" exists for every firm.
    fm_to_rownum: dict[tuple[str, str], int] = {}

    # Step 1: assign row numbers (1-indexed, global across all firms)
    for i, row in enumerate(sorted_rows, start=1):
        fm_to_rownum[(row["firm"], row["metric"])] = i

    # Step 2: rewrite formulas + assign feeds_rows
    work_rows = {}
    for i, row in enumerate(sorted_rows, start=1):
        firm = row["firm"]
        entry = {
            "metric": row["metric"],
            "firm": firm,
            "type": row["type"],
            "timeframe": row["timeframe"],
            "unit": row["unit"],
        }

        if row.get("ans"):
            entry["ans"] = True
        else:
            # Helper-only: find ALL consumers WITHIN SAME FIRM
            consumers = [
                fm_to_rownum[(r["firm"], r["metric"])]
                for r in sorted_rows
                if r["firm"] == firm
                and row["metric"] in _parse_formula_refs(
                    r.get("formula", "")
                )
            ]
            if consumers:
                entry["feeds_rows"] = sorted(consumers)

        if row.get("formula"):
            # Rewrite {MetricName} -> Rn (scoped to same firm)
            # Preserves [-k]/[+k] suffixes: {Revenue}[-1] → R1[-1]
            # Sort refs longest-first to avoid collision:
            # str.replace("{Revenue}") would corrupt "{Revenue Growth}"
            # since "{Revenue}" is a substring. Longest-first ensures
            # "{Revenue Growth}" is replaced before "{Revenue}".
            formula = row["formula"]
            refs = _parse_formula_refs(row["formula"])
            refs_sorted = sorted(refs, key=len, reverse=True)
            for ref_name in refs_sorted:
                rn = fm_to_rownum[(firm, ref_name)]
                formula = formula.replace(f"{{{ref_name}}}", f"R{rn}")
            entry["formula"] = formula

        work_rows[str(i)] = entry

    # Step 2b: Guard: unit not in canonical set
    import json
    units_path = (
        Path(__file__).resolve().parent
        / "hardcode_dependencies" / "units.json"
    )
    valid_units = json.loads(units_path.read_text())
    for row_num, row in work_rows.items():
        if row["unit"] not in valid_units:
            raise ValueError(
                f"Row {row_num} ({row['metric']}): "
                f"unit '{row['unit']}' not in {valid_units}."
            )

    # Step 3: build values map (all null)
    values = {}
    for col in col_letters:
        for row_num in work_rows:
            values[f"{col}{row_num}"] = None

    work_stencil = {
        "firms": firms,
        "periods": periods,
        "col_letters": col_letters,
        "rows": work_rows,
        "values": values,
        "sources": {},
    }

    # Step 4: build ans stencil (row_mapping is per-firm)
    # Metric names are already plain (no prefix to strip).
    row_mapping = {}  # {firm: {metric: row_num}}
    for row_num, row in work_rows.items():
        if row.get("ans"):
            firm = row["firm"]
            row_mapping.setdefault(firm, {})[row["metric"]] = int(row_num)

    ans_stencil = {
        "metrics": list(dict.fromkeys(
            row["metric"] for row in sorted_rows if row.get("ans")
        )),
        "periods": periods,
        "firms": firms,
        "col_letters": col_letters,
        "row_mapping": row_mapping,
        "filled": {},
    }

    # Step 5: dry-run formula syntax (catch bad formulas here,
    # not 30min later in Phase 2)
    from src.scripts.PMS2.stencil_safe_math import _safe_math_eval
    for row_num, row in work_rows.items():
        formula = row.get("formula")
        if not formula:
            continue
        # Substitute all Rn and Rn[-k]/Rn[+k] refs with 1.0
        test_expr = re.sub(r"R\d+(\[[+-]?\d+\])?", "1.0", formula)
        try:
            _safe_math_eval(test_expr)
        except (ValueError, ZeroDivisionError) as e:
            raise ValueError(
                f"Bad formula syntax in row {row_num} "
                f"({row['metric']}): '{formula}' — {e}"
            )

    # Step 6: split into job stencils (filter by firm, not deep copy)
    job_stencils = []
    for firm in firms:
        firm_rows = {
            rn: row for rn, row in work_rows.items()
            if row["firm"] == firm
        }
        firm_values = {
            cid: v for cid, v in values.items()
            if cid.lstrip("ABCDEFGHIJKLMNOPQRSTUVWXYZ") in firm_rows
        }
        job_stencils.append({
            "firm": firm,
            "periods": periods,
            "col_letters": col_letters,
            "rows": firm_rows,
            "values": firm_values,
            "sources": {},
        })

    return work_stencil, ans_stencil, job_stencils
```

```python
_Q_PREFIXES = ("Q1", "Q2", "Q3", "Q4")
_H_PREFIXES = ("H1", "H2")

def _expand_periods(periods: list[str], granularity: str) -> list[str]:
    """Expand FY periods by granularity. Already-expanded pass through.

    Guard: annual granularity + Q/H-prefixed period = contradiction.
    Orchestrator should not produce this. Raise so it surfaces
    loudly rather than silently extracting wrong timeframes.
    """
    if granularity == "annual":
        # Guard: Q/H prefix with annual = contradiction
        for p in periods:
            if p.startswith(_Q_PREFIXES + _H_PREFIXES):
                raise ValueError(
                    f"Period '{p}' has quarterly/half prefix but "
                    f"granularity is 'annual'. Fix orchestrator params."
                )
        return periods

    expanded = []
    for p in periods:
        if p.startswith(_Q_PREFIXES + _H_PREFIXES):
            # Already expanded (e.g. "Q3FY2025"), pass through
            expanded.append(p)
        elif granularity == "quarterly":
            for q in _Q_PREFIXES:
                expanded.append(f"{q}{p}")
        elif granularity == "half":
            for h in _H_PREFIXES:
                expanded.append(f"{h}{p}")
    return list(dict.fromkeys(expanded))  # dedup, preserve order
```

Sekei sees expanded periods in its initial prompt (e.g.
`["Q1FY2025","Q2FY2025","Q3FY2025","Q4FY2025"]` or
`["Q3FY2025"]` if user asked for a single quarter). Per-row
`timeframe` set to granularity value (default applied to all
rows, overridable per-row by Sekei).

the company labels "FY2026." Semantic mismatch (user's
mental model vs company's fiscal calendar) is **PTECA's
problem** — PMS2 extracts faithfully, PTECA handles
cross-firm temporal alignment.

**Fiscal Calendar Resolver (quarterly/half)**: for non-annual
granularity, the FY=CY assumption breaks at the quarter level
(LITE's Q1 = Jul-Sep, not Jan-Mar). Dispatcher spawns a
FiscalCalResolver per firm before the extraction loop — a
single `structured_complete(..., web_search=True)` call that
looks up the firm's fiscal year-end date and returns a
structured calendar mapping each period label to actual
calendar dates. This calendar is injected into every Leng
and Validator call so they can match "ended Sep 30, 2024"
to "Q1FY2025." See **Fiscal Calendar Resolver** section
under Phase 1 for full spec.

### Python post-processing (inside finalize handler)

When `finalize_stencil` is called, the handler:

**`session_dir`** = orchestrator's session dir, passed via
DD2. PMS2 writes into `session_dir/pms2/` subdirectory
(created by `run_pms2_pipeline`). No separate timestamp —
shares the orchestrator's session for co-located artifacts.

1. Validates `firms` and `periods` against pipeline args:
   - Subset OK (Sekei can drop firms/periods mid-conversation)
   - Superset or typo = error returned to Sekei for self-correction
   - `if set(params["firms"]) - set(pipeline_firms): error`
   - `if set(params["periods"]) - set(expanded_periods): error`
   - Exact string match — no fuzzy. Sekei's initial prompt
     contains the exact strings, echo errors = LLM fumble.
   - **Period ordering**: use pipeline's expanded periods filtered
     to Sekei's submitted set, preserving canonical order. Sekei
     can omit periods but CANNOT reorder them. Python:
     `periods = [p for p in expanded_periods if p in set(params["periods"])]`.
     This prevents column-letter mapping drift if Sekei scrambles order.
   - **Missing firms warning**: if `set(pipeline_firms) - set(params["firms"])` is non-empty, print `"⚠ {missing} not in stencil — dropped"` to CLI via channel.print. Not a blocking error — subset is valid (user may have narrowed scope during T3 preview). Warning so silent LLM fumbles surface.
2. Validates all formula refs exist as metric names
3. Runs `_topo_sort_rows` → sorted row order
4. Runs `_assign_structure` → work stencil, ans stencil, job stencils.
   Includes dry-run formula syntax check: substitutes 1.0 into
   each Rn formula, calls `_safe_math_eval()`. On failure,
   returns error to Sekei for self-correction.
5. Saves to disk (Phase 0 snapshot — pre-fill, for debugging):
   - `(session_dir / "pms2").mkdir(parents=True, exist_ok=True)`
   - `{session_dir}/pms2/work_stencil.json` (all null values, audit baseline)
   Phase 2 overwrites `work_stencil.json` and writes
   `ans_stencil.json` after filling. Job stencils are
   ephemeral (in-memory only, never written to disk).
6. Returns `(work_stencil, ans_stencil, job_stencils, file_inventories)`
   `file_inventories` = `{firm: "$var_N"}` — opaque registry
   handles from `run_mapper`. The `run_mapper` handler in
   `sekei_loop.py` calls `registry.store(inv, ...)` per firm
   and writes the handle string into `file_inventories[firm]`.
   `run_pms2_pipeline` resolves these via
   `registry.resolve(handle)` before passing to Dispatchers.
   **Plumbing**: `file_inventories` dict is a mutable variable in
   the Sekei agent loop scope (e.g. `file_inventories = {}`).
   The `run_mapper` handler writes handles to it (closure capture).
   The `finalize_stencil` handler passes it through unchanged
   (same closure). Same pattern for `session_dir`,
   `expanded_periods`, `pipeline_firms` — all captured from
   `run_pms2_pipeline` → Sekei loop scope.
   **M3b+ note**: Dispatcher code must call
   `registry.resolve(file_inventories[firm])` to get the
   actual `list[dict]` inventory — the dict values are handle
   strings, not data.

**Error recovery**: if topo sort, validation, or formula syntax
check fails (unknown metric reference, circular dependency,
missing formula for compute row, bad arithmetic syntax), the
error message is returned as the tool result
to Sekei. Sekei inspects the error, revises its stencil, and
re-calls `finalize_stencil`. Standard tool-calling error
recovery. Turn budget (max 8) is generous enough to absorb
1-2 errors.

Sekei transcript is NOT passed to Batch Planner. All structural
decisions (metrics, formulas, units) are embedded in the job
stencil. Source-routing comes from BP's own `ask_user`.

```python
def _walk_dirs(
    dirs: list[str], data_dir: Path, manifest: dict,
) -> list[dict]:
    """Walk directories, collect file inventory with filetype."""
    files = []
    for d in dirs:
        target = data_dir / d
        for root, _, filenames in os.walk(target):
            for fname in filenames:
                if fname.startswith(".") or fname.endswith(".json"):
                    continue
                fpath = Path(root) / fname
                rel = str(fpath.relative_to(data_dir))
                filetype = manifest.get(rel, "unknown")
                files.append({
                    "path": rel,
                    "filetype": filetype,
                    "filesize": fpath.stat().st_size,  # .md size, not original — BP heuristics still valid (bigger md = more content)
                })
    return files
```

## Phase 1: Dispatcher

**Python loop, one per firm, all firms run in parallel.**

**Concurrency**: no thread pool limits anywhere in the pipeline.
Mapper agents, Dispatchers, Leng calls, Validators — all fire
unbounded. No semaphores needed — Scale tier gives 10K RPM
for Haiku, peak concurrent calls ~200. API rate limits are
the natural backpressure. These are I/O-bound calls; threads
waiting on HTTP responses cost nothing.

**Trace labels** (per Spec 15, all LLM calls captured):

| Agent | Label format |
|---|---|
| Sekei | `"PMS2-sekei"` |
| Mapper | `"PMS2-map-{firm}"` |
| FiscalCalResolver | `"PMS2-fiscal-{firm}"` |
| Batch Planner | `"PMS2-bp-{firm}-#{iteration}"` |
| Leng | `"PMS2-leng-{firm}-{node_id}"` |
| Validator | `"PMS2-確認-{firm}-{node_id}"` |

The Dispatcher is a thin loop. It checks for remaining null
cells, prunes satisfied helpers, fires Batch Planner (which
owns execution and exhaustion judgment). Dispatcher's only
safety net: dry run counter (consecutive iterations with 0
new cells filled). After `_MAX_DRY_RUNS` (2) dry runs,
Dispatcher force-asks the user. All extraction logic lives
inside Batch Planner → LengCaller → Validator chain.

### Dispatcher state

```python
_MAX_DRY_RUNS = 2  # consecutive iterations with 0 new cells → force ask user

@dataclass
class DispatcherState:
    """Per-firm state owned by the Dispatcher loop."""
    firm: str
    job_stencil: dict             # live, mutated in-place by Validators
    file_inventory: list[dict]    # full file list from Mapper (immutable)
    searched_files: dict          # {file_path: {cells_searched, cells_found}}
    iteration: int                # current loop iteration (0-indexed)
    dry_run_count: int            # consecutive iterations with 0 new cells filled
    status: str                   # "running" | "complete" | "user_aborted" | "bp_exhausted"
    stencil_lock: threading.Lock  # single lock for job_stencil writes
    fiscal_calendar: dict | None  # {Q1FY2025: "Jul 1 2024–Sep 30 2024", ...} or None (annual / resolver failed)
```

### searched_files structure

```python
searched_files = {
    "LITE/Company/LITE_10K_2025.md": {
        "cells_searched": ["A1", "B1", "C1", "A2", "B2", "C2",
                           "A5", "B5", "C5"],
        "cells_found": ["A1", "B1", "A2", "B2", "A5"],
        "rejections": {
            "C2": "unit mismatch: JPY vs USD",
        },
        "leng_errors": [],
    },
    "LITE/Notes/LITE 2Q beat_ and guided 3Q.md": {
        "cells_searched": ["C1", "C2", "B5", "C5"],
        "cells_found": ["C1"],
        "rejections": {},
        "leng_errors": ["chunk abc123: timeout"],
    },
}
```

**`rejections`** maps cell_id → rejection reason string. Populated
from Validator outcomes where `action == "reject"`. Gives BP
signal about WHY a cell wasn't found — crucial for unit mismatch
patterns (e.g. "all cells rejected on unit mismatch CNY vs USD"
→ BP can ask user about currency). Empty dict when no rejections.

**`leng_errors`** list of `"{node_id}: {error}"` strings. Populated
when a Leng `structured_complete` call crashes after retries
(timeout, API error, malformed JSON). Gives BP signal that
chunks crashed vs genuinely missed — BP can reason "2/50 chunks
crashed, might be worth retrying this file." Empty list when
no errors. LengCaller also emits `channel.print("⚠ Leng
chunk {node_id} crashed: {e}")` per crash for CLI visibility.

Batch Planner sees this and can reason: "10K was tried for C2
but didn't have it. Model xlsx wasn't tried yet — likely has
forward estimates." Batch Planner is NOT hard-blocked from
re-trying files already in searched_files — it can reason that
a file might contain a value under a different section name or
table format.

LengCaller is the single writer to `searched_files`. After all
Validators finish for a `run_leng_caller` invocation, LengCaller
populates per-file entries from Validator outcomes.
`cells_found` = cells whose Validators confirmed valid
(either "written" or "skipped: already filled" from a race).
This gives BP richer signal about file quality — a file that
lost a race still had the data.

### Dispatcher loop

```python
def run_dispatcher(
    firm: str,
    job_stencil: dict,
    file_inventory: list[dict],
    granularity: str,
    periods: list[str],
    channel: ToolChannel,
    config: Config,
    docstore,                     # SimpleDocumentStore (loaded once, read-only)
    file_path_index: dict,        # {file_path: {node_ids, filetype}} (loaded once, read-only)
    debug_dir: Path | None = None,  # trace output directory
) -> dict:
    """Phase 1 extraction loop for one firm.

    Returns filled job_stencil with status field.

    Exhaustion is primarily BP's judgment (via report_exhausted
    terminal tool after ask_user). Dispatcher counts dry runs
    (consecutive iterations with 0 new cells) as safety net —
    after _MAX_DRY_RUNS, Dispatcher force-asks the user.
    """
    stencil_lock = threading.Lock()

    # PRE-LOOP: Fiscal Calendar Resolver (non-annual only)
    fiscal_calendar = None
    if granularity != "annual":
        fiscal_calendar = _resolve_fiscal_calendar(
            firm=firm,
            periods=periods,
            config=config,
            channel=channel,
        )
        # fiscal_calendar is None on failure — degrade, don't crash

    state = DispatcherState(
        firm=firm,
        job_stencil=job_stencil,
        file_inventory=file_inventory,
        searched_files={},
        iteration=0,
        dry_run_count=0,
        status="running",
        stencil_lock=stencil_lock,
        fiscal_calendar=fiscal_calendar,
    )

    while state.status == "running":
        # Step 1: check for remaining null ans cells
        null_ans_cells = _get_null_ans_cells(state.job_stencil)
        if not null_ans_cells:
            state.status = "complete"
            break

        # Step 2: helper cell pruning
        active_cells = _prune_satisfied_helpers(
            state.job_stencil, null_ans_cells
        )

        # Snapshot filled count before BP runs
        filled_before = sum(
            1 for v in state.job_stencil["values"].values()
            if v is not None
        )

        # Step 3: call Batch Planner (agent loop)
        # BP has two terminal tools:
        #   run_leng_caller(plan) — fire extraction plan
        #   report_exhausted(reason) — BP judged further search pointless
        # BP can ask_user before either terminal tool.
        # Iteration count + max passed in prompt so BP can reason
        # about coverage.
        bp_result = run_batch_planner(
            firm=state.firm,
            job_stencil=state.job_stencil,
            active_cells=active_cells,
            file_inventory=state.file_inventory,
            searched_files=state.searched_files,
            iteration=state.iteration,
            stencil_lock=stencil_lock,
            fiscal_calendar=state.fiscal_calendar,
            channel=channel,
            config=config,
            docstore=docstore,
            file_path_index=file_path_index,
            debug_dir=debug_dir,
        )

        # Step 4: check BP exit reason
        if bp_result == "exhausted":
            # BP asked user and user said stop
            state.status = "bp_exhausted"
            break

        # Step 5: dry run safety net
        null_ans_cells = _get_null_ans_cells(state.job_stencil)
        if not null_ans_cells:
            state.status = "complete"
            break

        filled_after = sum(
            1 for v in state.job_stencil["values"].values()
            if v is not None
        )
        if filled_after > filled_before:
            state.dry_run_count = 0
        else:
            state.dry_run_count += 1

        if state.dry_run_count >= _MAX_DRY_RUNS:
            # Safety net: BP didn't call report_exhausted but
            # nothing is being found. Force-ask user.
            missing_desc = _describe_missing_cells(
                state.job_stencil, null_ans_cells
            )
            answer = channel.input(
                f"{state.iteration + 1} iterations for {firm}, "
                f"{state.dry_run_count} found nothing. "
                f"Still missing: {missing_desc}. continue? [y/n]"
            )
            if answer.strip().lower().startswith("y"):
                state.dry_run_count = 0  # reset, give BP another chance
            else:
                state.status = "user_aborted"
                break

        state.iteration += 1

    job_stencil["status"] = state.status
    # status is informational only — Phase 2 does not branch on it.
    # Exhausted/aborted firms pass through with nulls. No retry,
    # no recursive Sekei recall. Future iteration scope.
    return job_stencil
```

### Fiscal Calendar Resolver

Runs once per firm in Dispatcher, before the extraction loop.
Only fires when `granularity != "annual"`. Single
`structured_complete(..., web_search=True)` call — Haiku
searches for the firm's fiscal year-end date, then computes
the calendar date range for each period in the stencil.

**Why**: quarterly/half periods are ambiguous without knowing
the firm's fiscal calendar. "Q1FY2025" means Jan-Mar for a
Dec-FY company, but Jul-Sep for a Jun-FY company (e.g. LITE).
Without the calendar, Leng either grabs wrong-quarter data
or misses entirely. Annual is forgiving (documents label
"FY2025" and Leng matches); quarterly is not.

**Not injected into Batch Planner.** BP reasons about files,
not period semantics. It doesn't need to know that Q1 = Jul-Sep.
Only Leng (extraction) and Validator (verification) need the
calendar to match "ended Sep 30, 2024" to "Q1FY2025."

```python
_FISCAL_CAL_MAX_RETRIES = 3

def _resolve_fiscal_calendar(
    firm: str,
    periods: list[str],
    config: Config,
    channel: ToolChannel,
) -> dict | None:
    """Look up firm's fiscal year-end, return period→date mapping.

    3 attempts via structured_complete(web_search=True).
    On total failure, falls back to ask_user for freeform
    fiscal calendar info, then structured_complete (no
    web_search) to parse user text into calendar dict.
    Returns None only if everything fails.
    """
    backend = get_pms2_fiscal_cal_llm(config)

    schema = {
        "type": "object",
        "properties": {
            "fy_end_month_day": {
                "type": "string",
                "description": "Fiscal year end as 'Month Day', e.g. 'June 30', 'December 31'",
            },
            "calendar": {
                "type": "object",
                "additionalProperties": {
                    "type": "string",
                    "description": "Date range, e.g. 'Jul 1 2024 – Sep 30 2024'",
                },
                "description": "Map of each period label to calendar date range",
            },
        },
        "required": ["fy_end_month_day", "calendar"],
    }

    web_prompt = (
        f"What is {firm}'s fiscal year-end date? "
        f"Search the web to confirm.\n\n"
        f"Then compute the calendar date range for each of "
        f"these periods:\n"
        + "\n".join(f"  {p}" for p in periods)
        + "\n\nFor example, if the company's fiscal year ends "
        f"June 30, then Q1FY2025 = Jul 1 2024 – Sep 30 2024, "
        f"H1FY2025 = Jul 1 2024 – Dec 31 2024, "
        f"FY2025 = Jul 1 2024 – Jun 30 2025."
    )

    # --- Phase 1: web search (3 attempts) ---
    for attempt in range(_FISCAL_CAL_MAX_RETRIES):
        try:
            result = backend.structured_complete(
                prompt=web_prompt,
                schema=schema,
                label=f"PMS2-fiscal-{firm}",
                web_search=True,
            )
            calendar = result.get("calendar", {})
            if calendar:
                channel.print(
                    f"[PMS2-fiscal-{firm}] FY ends "
                    f"{result.get('fy_end_month_day', '?')}. "
                    f"Calendar: {len(calendar)} periods resolved."
                )
                return calendar
        except Exception:
            pass
        channel.print(
            f"[PMS2-fiscal-{firm}] attempt {attempt + 1}/"
            f"{_FISCAL_CAL_MAX_RETRIES} failed"
        )

    # --- Phase 2: ask user fallback ---
    user_text = channel.input(
        f"[PMS2-fiscal-{firm}] fiscal cal resolver broken atm. "
        f"what is the calendar equivalent of {firm}'s fiscal "
        f"years/halves/quarters?"
    )

    parse_prompt = (
        f"The user provided this fiscal calendar info for {firm}:\n"
        f'"{user_text}"\n\n'
        f"Parse it into calendar date ranges for these periods:\n"
        + "\n".join(f"  {p}" for p in periods)
    )

    try:
        result = backend.structured_complete(
            prompt=parse_prompt,
            schema=schema,
            label=f"PMS2-fiscal-{firm}-user",
            web_search=False,
        )
        calendar = result.get("calendar", {})
        if calendar:
            channel.print(
                f"[PMS2-fiscal-{firm}] parsed from user input. "
                f"{len(calendar)} periods resolved."
            )
            return calendar
    except Exception:
        pass

    # --- Total failure ---
    channel.print(
        f"[PMS2-fiscal-{firm}] fiscalcalresolver shat the bed. "
        f"forcing onward with no fiscal cal dict"
    )
    return None
```

**Retry + fallback chain:** 3x web_search retries → ask_user
freeform → structured_complete (no web_search, single shot)
to parse user text → None on total failure ("shat the bed").

**Failure modes and mitigations:**

| Failure | Impact | Mitigation |
|---|---|---|
| Web search fails 3x | Falls back to ask_user. User provides FY info manually. | 3 retries absorb transient failures. User fallback for persistent. |
| User fallback parse fails | No calendar. Leng operates blind (same as annual). | Print "shat the bed", proceed. Analyst knows. |
| Haiku gets wrong FY end | All quarter mappings wrong. Systematic wrong extractions. **Worse than no mapping.** | Hard to detect. Validator has same wrong calendar — no cross-check. Accepted risk for demo. |
| Firm name ambiguity | "LITE" → wrong company → wrong FY end | Use full company name from Mapper results if available, not just ticker |
| FY end changed mid-history | Historical periods mapped to wrong dates | Rare. Accepted for demo. |
| H1/H2 granularity | Half-year needs correct date ranges too | Resolver prompt covers H1/H2 format |

**Cost**: one Haiku call per firm (up to 3 retries + 1 user
fallback parse = 5 calls worst case). ~500 tok in, ~200 tok
out per call. Negligible.

**Passthrough chain**: `fiscal_calendar` flows Dispatcher →
`run_batch_planner()` (passed as arg, NOT in BP's tool schema
— BP never sees it) → `run_leng_caller` handler (captured
via closure/arg, same pattern as `stencil_lock`) → each Leng
prompt (appended to cell descriptions) → each Validator prompt
(appended to input). Pure Python plumbing at every hop. BP
calls `run_leng_caller(plan)` with just the plan; Python
injects `fiscal_calendar` from the enclosing scope.

**Trace**: captured under label `"PMS2-fiscal-{firm}"`. One
trace entry per firm, logged in `Dispatcher_{firm}_iter0.md`
(fires before the loop but in the Dispatcher trace context).

### Helper cell pruning

```python
def _get_null_ans_cells(job_stencil: dict) -> list[str]:
    """Return cell IDs for ans rows that are still null."""
    null_cells = []
    for row_num, row in job_stencil["rows"].items():
        if not row.get("ans"):
            continue
        for col in job_stencil["col_letters"]:
            cell_id = f"{col}{row_num}"
            if job_stencil["values"].get(cell_id) is None:
                null_cells.append(cell_id)
    return null_cells


def _prune_satisfied_helpers(
    job_stencil: dict, null_ans_cells: list[str],
) -> list[str]:
    """Return cells to search: null ans cells + unsatisfied helpers.

    Cell-level pruning: a helper CELL {col}{row} is excluded if
    ALL consumer cells in the SAME COLUMN are already filled.
    e.g. B1 (Revenue FY26, feeds GM row 5) is pruned if B5 is
    filled, even if A5 and C5 are still null.
    """
    active = list(null_ans_cells)

    for row_num, row in job_stencil["rows"].items():
        if row.get("ans"):
            continue  # already in active via null_ans_cells
        feeds_list = row.get("feeds_rows")
        if not feeds_list:
            continue

        # Per-column check: is this helper cell still needed?
        for col in job_stencil["col_letters"]:
            cell_id = f"{col}{row_num}"
            if job_stencil["values"].get(cell_id) is not None:
                continue  # already filled, skip

            # Check if ANY consumer in this column still has nulls
            any_consumer_null = any(
                job_stencil["values"].get(f"{col}{feeds}") is None
                for feeds in feeds_list
            )
            if any_consumer_null:
                active.append(cell_id)
            # else: all consumers in this column filled -> prune

    return active


```

## Batch Planner

Agent loop (max 4 turns). Called by Dispatcher **each iteration**
— fresh LLM invocation with updated state. Not a persistent
multi-turn conversation across iterations.

**Two terminal tools**: `run_leng_caller` (fire extraction plan)
and `report_exhausted` (declare further searching pointless).
BP can `ask_user` before either — e.g. "tried 12/15 files,
remaining are sector PDFs, still missing C2. Stop?" If user
says stop → `report_exhausted`. If user gives a hint →
`run_leng_caller` with revised plan.

**Iteration awareness**: BP prompt includes current iteration
number so it can reason about coverage and when to suggest
exhaustion. BP sysprompt: prefer hedging (assigning same
cell to multiple files) over asking the user. `ask_user`
for routing advice or exhaustion judgment, not routine
decisions.

### override_firm_currency handler

Atomic override of all non-float rows for a firm. Mutates
job stencil rows in place — which are shared refs to work
stencil rows, so work stencil picks up the change for free.
Ans stencil has no unit field. Display stencil reads
`row["unit"]` from work stencil at serialize time — inherits
override naturally. Zero propagation code.

```python
def _handle_override_firm_currency(
    params: dict,
    job_stencil: dict,
    valid_units: list[str],
) -> str:
    """Override currency for ALL non-float rows of a firm. Atomic."""
    firm = params["firm"]
    new_unit = params["new_unit"]

    if new_unit not in valid_units:
        return f"Error: '{new_unit}' not in {valid_units}"
    if new_unit == "float":
        return "Error: cannot override currency to 'float'"

    # Collect targets: all non-float rows for this firm
    # (retrieve + compute — EBITDA in CNY must flip to USD
    # when its inputs flip)
    targets = [
        (rn, row) for rn, row in job_stencil["rows"].items()
        if row["firm"] == firm
        and row["unit"] != "float"
    ]

    if not targets:
        return f"Error: no currency rows for {firm}"

    # Guard: reject if any non-float values already written.
    # Override after partial extraction = silent wrong values
    # (absolute number in old currency, now labeled as new).
    for rn, row in targets:
        for col in job_stencil["col_letters"]:
            cell_id = f"{col}{rn}"
            if job_stencil["values"].get(cell_id) is not None:
                return (
                    f"Error: {cell_id} ({row['metric']}) already "
                    f"filled. Cannot override currency after partial "
                    f"extraction — values would be wrong."
                )

    old_unit = targets[0][1]["unit"]
    for rn, row in targets:
        row["unit"] = new_unit  # mutates work stencil too (shared ref)

    return (
        f"Overrode {len(targets)} rows for {firm}: "
        f"{old_unit} → {new_unit}"
    )
```

### Input

Each Batch Planner invocation receives (in initial prompt):
1. Job stencil JSON for that firm (showing current fill state —
   which cells are null, which are filled)
2. File inventory for that firm (from Mapper)
3. searched_files (which files were tried, what was found/missed)
4. Active cells (from Dispatcher's helper pruning)
5. Current iteration number (0-indexed) — so BP can reason
   about coverage depth and when to suggest exhaustion

No Sekei transcript — all structural decisions are embedded
in the job stencil (metrics, formulas, units, timeframes).
Source-routing hints come from BP's own `ask_user`, not Sekei.

**Prompt size risk**: `searched_files` grows across iterations.
With large corpora (50+ files × many iterations), BP's initial
prompt could get large. Acceptable for demo (corpus ~10 files
per firm, ≤3 iterations typical). Post-demo: consider
summarizing or truncating `searched_files` if prompt size
becomes a cost/context issue.

### LLM reasoning

No hardcoded routing. The LLM reasons about filenames, filetypes,
file sizes, AND previous search results to decide which files
to try next and which cells to assign.

**BP has never read file contents.** It sees filenames, filetypes,
sizes, and searched_files outcomes — nothing more. BP sysprompt
must enforce: never claim what a file contains, only speculate
from filename. e.g. "filenames don't suggest FY26 available,
me missing smt?" not "this file doesn't have FY26 data."

**First iteration**: Batch Planner has no searched_files history.
It routes based on filename/filetype/size heuristics:

```
"Lumentum-results-2026.md (pdf, 1.2mb) -> likely has 3-stmt items"
"RICHARD HO.md (docx, 84kb) -> analyst notes, likely has estimates"
```

**Subsequent iterations**: Batch Planner sees what was tried and
what failed. It can reason about alternatives:

```
"10K was tried for GP FY27 (C2) but REJECTED — forward year
 not in historical filing. Try analyst notes or model for
 forward estimates."
```

**Confidence gradient for cell assignment:**

1. **Confident**: cell → one file. The typical case. LLM picks
   the most likely file.

2. **Moderate uncertainty**: cell duplicated across files.
   When the LLM isn't sure which file has a cell's value,
   it assigns that cell to multiple file entries in the plan.
   LengCaller searches all in parallel. **First-write-wins
   with lock**: `values[cell_id]` compare-and-swap — if null,
   write; if already filled, skip. Non-deterministic (race
   between Validators). This is deliberate hedging — marginal
   cost (a few extra Leng calls on a cheap model) for significant
   robustness gain.

3. **Low confidence**: `ask_user` before committing the plan.
   When the LLM cannot make a reasonable guess, it asks the
   user before calling `run_leng_caller`.

Compute cells go into the plan. Leng tries to find them
directly. If found, their feeder rows can be pruned in the
next Dispatcher iteration.

## LengCaller

Python. The `run_leng_caller` tool handler. Called by Batch
Planner as its terminal tool. Receives a file-centric plan,
executes everything in parallel, returns "complete".

Chains: chunk fetch → Leng × N → Validator per hit. No LLM
reasoning at this level — pure orchestration.

### LengCaller flow

### Validator → LengCaller plumbing

Each Validator thread returns structured outcomes to LengCaller
(not just the agent-loop string). `_handle_submit_verdicts`
returns a **tuple** `(cell_outcomes, status_string)` following
the terminal tool convention `(data, status_string)`.
`cell_outcomes` is a list of `(cell_id, outcome, reason)`
tuples where outcome ∈ `{"written", "skipped", "rejected"}`
and reason is the rejection reason string (empty for
non-rejections). `status_string` is the semicolon-joined
per-cell summary (fed back to the LLM as the tool result).
The agent loop scaffold's `_handle_terminal` returns
`(data, status_string)` — `data` becomes `terminal_result`
(returned from agent loop to LengCaller), `status_string`
becomes the tool result content sent to the LLM. The
Validator runner function (called by LengCaller via
ThreadPoolExecutor) receives `terminal_result` =
`cell_outcomes` directly.
LengCaller collects these per-file:

```python
# In LengCaller, after spawning Validator threads:
# Each validator future returns:
#   (file_path, [(cell_id, outcome, reason), ...])
#
# IMPORTANT: wrap each fut.result() in try/except. A single
# Validator crash (Haiku garbage, agent loop error) must not
# kill the entire LengCaller → Dispatcher chain. Treat crash
# as miss (0 cells found for that chunk). Log the exception
# via channel.print for debugging.
#
# Collect Leng errors per file (from Leng futures, before
# Validator futures). leng_errors_by_file populated during
# Leng future collection (see Leng error handling section):
#   leng_errors_by_file = defaultdict(list)
#   for fut in as_completed(leng_futures):
#       try: ... except Exception as e:
#           leng_errors_by_file[file_path].append(f"{node_id}: {e}")
#
# Collect Validator outcomes into per-file cells_found + rejections:
# Accumulate per-file results from this LengCaller invocation:
this_run_found: dict[str, list] = defaultdict(list)
this_run_rejections: dict[str, dict] = defaultdict(dict)

for fut in as_completed(validator_futures):
    try:
        file_path, cell_outcomes = fut.result()
    except Exception as e:
        # Absorb — one bad Validator out of 50 must not
        # take down the firm's entire extraction.
        channel.print(f"⚠ Validator crashed: {e}")
        continue
    for cid, out, reason in cell_outcomes:
        if out in ("written", "skipped"):
            this_run_found[file_path].append(cid)
        elif out == "rejected" and reason:
            this_run_rejections[file_path][cid] = reason

# Merge into searched_files (append, don't overwrite —
# same file can be searched across multiple iterations):
for file_path in plan_entry_cells:
    existing = searched_files.get(file_path)
    if existing:
        existing["cells_searched"] = list(set(
            existing["cells_searched"] + plan_entry_cells[file_path]
        ))
        existing["cells_found"] = list(set(
            existing["cells_found"] + this_run_found.get(file_path, [])
        ))
        existing["rejections"].update(
            this_run_rejections.get(file_path, {})
        )
        existing["leng_errors"].extend(
            leng_errors_by_file.get(file_path, [])
        )
    else:
        searched_files[file_path] = {
            "cells_searched": plan_entry_cells[file_path],
            "cells_found": this_run_found.get(file_path, []),
            "rejections": this_run_rejections.get(file_path, {}),
            "leng_errors": leng_errors_by_file.get(file_path, []),
        }
```

"skipped" (race-lost) still counts as "found" — the file
had the data, BP should know. "rejected" = file didn't have
it or value was wrong. Rejection reasons propagated to BP
via `rejections` dict — gives BP signal about unit mismatches,
period mismatches, etc. for subsequent iterations.

### Leng output contract

Simple. No term derivation, no cleverness. Extract what's
in the chunk, null for everything else. Per cell, Leng reports
the value as-written, the denomination the source uses, and
the unit (what kind of thing the value is).

**Output mechanism**: `structured_complete()` in `llm.py` — JSON
mode where provider supports it, tool-calling fallback for
providers that don't (e.g. Anthropic). Leng code calls a single
method, backend picks mechanism.

**All cells assigned to this file (from BP plan entry) sent to
every chunk of that file.** No per-chunk filtering by metadata.
Leng is cheap, let it look at everything. Filtering logic =
hardcode = forbidden.

**JSON schema for `structured_complete()`:**

**Error handling**: `llm.py` retries transient errors (429, 500,
timeout) with exponential backoff. LengCaller wraps each Leng
future collection in try/except — if `structured_complete`
raises after retries, treat as miss (same as `found: false`).
Emit `channel.print("⚠ Leng chunk {node_id} crashed: {e}")`
and append `"{node_id}: {error_summary}"` to the per-file
`leng_errors` list in `searched_files`. BP sees crash count
per file and can reason about retry-worthiness.

**Per-cell fields:**

| Field | Description |
|---|---|
| `value` | Number as-written in the source. Leng does NOT scale it. |
| `denom` | Denomination the source expresses the number in. Canonical set: `"units"`, `"k"`, `"mn"`, `"bn"`, `"tn"`, `"%"`, `"bps"`. Detected from chunk context (e.g. `"$ in millions"` → `"mn"`, `"32.8%"` → `"%"`, `"15 bps"` → `"bps"`). If no denom evidence found in chunk or overlap context, report `"unknown"` — Validator gets a second chance to resolve from the same chunk text, rejects if still can't determine. |
| `unit` | What kind of thing: `"USD"`, `"JPY"`, `"float"`, etc. From canonical set defined in `src/scripts/PMS2/hardcode_dependencies/units.json` (`["USD","JPY","EUR","GBP","CNY","float"]`). Detected from chunk context (e.g. `"$"` → `"USD"`, `"¥"` → `"JPY"`, `"%"` → `"float"`, `"22.5x"` → `"float"`). |

`units.json` is the single source of truth for valid units:
`["USD", "JPY", "EUR", "GBP", "CNY", "float"]`.
Canonical label for Chinese currency is `"CNY"` (ISO standard).
Leng sysprompt instructs "prefer CNY", but sources may say
"RMB". `submit_verdicts` handler normalizes aliases in Python
before the exact-match unit check:
```python
_UNIT_ALIASES = {"RMB": "CNY"}  # Python safety net, not LLM-dependent
unit = _UNIT_ALIASES.get(unit, unit)
```
This runs before the `unit != expected_unit` check in
`_handle_submit_verdicts`. No dual-entry in `units.json`,
no LLM reliability dependency for alias resolution.
`"float"` = any dimensionless number: percentages, multiples (P/E = 15.2x),
counts (share count), ratios. No separate "x" unit — multiples are `"float"`.
**Display interpretation is downstream's burden** (PTECA infers from metric name — "margin"→%, "P/E"→x). PMS2 stores absolute float, no display_hint field. `"USD"` (or other currency) = any
currency-denominated value regardless of per-share or absolute
(Revenue, EPS, dividends all = `"USD"`). Denom handles scale.
Sekei sysprompt includes this list for row unit assignment.
Leng sysprompt includes this list + alias note (prefer CNY over RMB).
Validator does exact-match unit check against the stencil row's
unit, after alias normalization.

Cells not in the `cells` map = not found in this chunk.
`cells` is always present (empty object `{}` on miss).
LengCaller spawns a Validator **only when `cells` is non-empty**.
`found` flag is a hint for short-circuit — if `found: false`,
skip `cells` entirely. If `found: true` but `cells: {}` (LLM
fumble), treat as miss, no Validator spawned.

**`found` field fallback**: Haiku frequently omits the `found`
field entirely (returns `{"cells": {...}}` without it). Infer
from non-empty `cells` map:
`found = leng_output.get("found", bool(leng_cells))`.
Without this fallback, all hits are silently dropped.

Leng is type-agnostic: retrieve and compute cells are treated
identically. If Gross Margin appears literally in the chunk,
extract it. If not, return nothing — Phase 2 computes it from
components.

## Validator

Agent loop (max 2 turns) per Leng hit — NOT `structured_complete()`.
Why agent loop instead of structured output: hundreds of Validators
fire per pipeline run. Haiku fumbles tool calls ~2% of the time.
With `structured_complete`, a parse failure = raise = all cells
from that chunk silently lost. With agent loop, turn 2 sends the
error back and Haiku self-heals for ~$0.001. Cheap insurance
against silent data loss at scale.

1 Validator per chunk that returned `found: true`. All Validators
run in parallel (one thread per hit). Spawned immediately as each
Leng returns a hit — no batching or waiting.

One Validator handles ALL cells from its Leng hit. If Leng
found 4 cells in one chunk, one Validator verdicts all 4.

No `ask_user`. Ambiguity is resolved by reasoning, not user
interruption. If uncertain, Validator rejects — Dispatcher
retries with a different file if needed.

```python
# validator_loop.py
from src.scripts.PMS2.denom_reconcile import DENOM_FACTORS, _UNIT_ALIASES, _DENOM_ALIASES

def _handle_submit_verdicts(
    params: dict,
    job_stencil: dict,
    stencil_lock: threading.Lock,
    node_id: str,
) -> tuple[list[tuple], str]:
    """Process all verdicts from one Validator.

    Per verdict: unit check, denom normalize, lock, compare-and-swap.
    Returns (cell_outcomes, status_string) — matches terminal tool
    convention: (data_for_caller, string_for_LLM).
      cell_outcomes = [(cell_id, outcome, reason), ...] (for LengCaller)
        outcome ∈ {"written", "skipped", "rejected"}
      status_string = semicolon-joined per-cell summary (for LLM)
    """
    results = []
    cell_outcomes = []  # structured data for LengCaller

    # Guard: malformed top-level params
    verdicts = params.get("verdicts")
    if not verdicts or not isinstance(verdicts, list):
        return [], "Error: verdicts missing or not a list"

    for verdict in verdicts:
        cell_id = verdict.get("cell_id", "")
        action = verdict.get("action", "")
        if not cell_id or not action:
            results.append("?: rejected (missing cell_id or action)")
            cell_outcomes.append(("?", "rejected", "missing cell_id or action"))
            continue

        if action == "reject":
            reason = verdict.get("reason", "")
            results.append(f"{cell_id}: rejected ({reason})")
            cell_outcomes.append((cell_id, "rejected", reason))
            continue

        # action == "write" — guard missing/malformed fields
        value = verdict.get("value")
        denom = verdict.get("denom")
        unit = verdict.get("unit")

        if not isinstance(value, (int, float)) or value is None:
            reason = f"non-numeric value: {repr(value)}"
            results.append(f"{cell_id}: rejected ({reason})")
            cell_outcomes.append((cell_id, "rejected", reason))
            continue

        if not denom or not isinstance(denom, str):
            reason = f"missing or invalid denom: {repr(denom)}"
            results.append(f"{cell_id}: rejected ({reason})")
            cell_outcomes.append((cell_id, "rejected", reason))
            continue

        if not unit or not isinstance(unit, str):
            reason = f"missing or invalid unit: {repr(unit)}"
            results.append(f"{cell_id}: rejected ({reason})")
            cell_outcomes.append((cell_id, "rejected", reason))
            continue

        # Guard: cell_id must exist in stencil values map.
        # Prevents phantom cell writes from hallucinated cell IDs.
        if cell_id not in job_stencil["values"]:
            results.append(f"{cell_id}: error (cell not in stencil)")
            cell_outcomes.append((cell_id, "rejected", "cell not in stencil"))
            continue

        # Extract row number from cell_id
        row_num = cell_id.lstrip("ABCDEFGHIJKLMNOPQRSTUVWXYZ")
        row = job_stencil["rows"].get(row_num)
        if row is None:
            results.append(f"{cell_id}: error (unknown row {row_num})")
            cell_outcomes.append((cell_id, "rejected", f"unknown row {row_num}"))
            continue

        # Step 0.5: alias normalization (imported from denom_reconcile.py)
        unit = _UNIT_ALIASES.get(unit, unit)
        denom = _DENOM_ALIASES.get(denom, denom)

        # Step 1: unit check (canonical set from units.json)
        expected_unit = row.get("unit", "")
        if expected_unit and unit and unit != expected_unit:
            reason = f"unit mismatch: {unit} vs {expected_unit}"
            results.append(f"{cell_id}: rejected ({reason})")
            cell_outcomes.append((cell_id, "rejected", reason))
            continue

        # Step 2: denom normalize
        factor = DENOM_FACTORS.get(denom)
        if factor is None:
            reason = f"unknown denom '{denom}'"
            results.append(f"{cell_id}: rejected ({reason})")
            cell_outcomes.append((cell_id, "rejected", reason))
            continue

        absolute_value = value * factor

        # Step 3: lock + compare-and-swap
        with stencil_lock:
            if job_stencil["values"].get(cell_id) is not None:
                results.append(f"{cell_id}: skipped (already filled)")
                cell_outcomes.append((cell_id, "skipped", ""))
                continue
            job_stencil["values"][cell_id] = absolute_value
            job_stencil["sources"][cell_id] = node_id

        results.append(f"{cell_id}: written")
        cell_outcomes.append((cell_id, "written", ""))

    return cell_outcomes, "; ".join(results)
```

### Validator turn flow

```
CASE A: multi-cell confident (typical, 1 turn)
  Leng found A1, B1, A2, B2 in chunk abc123.
  Turn 1: LLM examines chunk, all values + denoms + units match
    -> submit_verdicts(verdicts=[
         {cell_id: "A1", action: "write", value: 43452, denom: "mn", unit: "USD"},
         {cell_id: "B1", action: "write", value: 51761, denom: "mn", unit: "USD"},
         {cell_id: "A2", action: "write", value: 10042, denom: "mn", unit: "USD"},
         {cell_id: "B2", action: "write", value: 12051, denom: "mn", unit: "USD"},
       ])
    -> handler: A1 written, B1 written, A2 written, B2 written
    -> DONE

CASE B: mixed write + reject (1 turn)
  Leng found A1, B1, C1 — but C1 is a forward estimate not in chunk.
  Turn 1: LLM confirms A1, B1 but C1 is wrong period
    -> submit_verdicts(verdicts=[
         {cell_id: "A1", action: "write", value: 43452, denom: "mn", unit: "USD"},
         {cell_id: "B1", action: "write", value: 51761, denom: "mn", unit: "USD"},
         {cell_id: "C1", action: "reject", reason: "FY27 not in this 10K filing"},
       ])
    -> DONE

CASE C: Leng got denom wrong on one cell (1 turn)
  Turn 1: Leng claimed denom="k" for A1 but chunk says "(in millions)"
    -> submit_verdicts(verdicts=[
         {cell_id: "A1", action: "write", value: 43452, denom: "mn", unit: "USD"},
       ])
    -> DONE (Validator corrected denom)

CASE D: race lost on some cells (1 turn)
  Turn 1: Validator confirms all 3 cells, submits
    -> handler: A1 written, B1 skipped (already filled), A2 written
    -> DONE (normal exit, "skipped" is fine)
```

Each Validator receives in its initial message:
```

Fiscal calendar (if available):
  Q1FY2025 = Jul 1 2024 – Sep 30 2024

  B1 = Revenue, Q2FY2025, quarterly, stencil unit=USD

  A2 = Gross Profit, Q1FY2025, quarterly, stencil unit=USD
    claimed: value=1560, denom=mn, unit=USD
  B2 = Gross Profit, Q2FY2025, quarterly, stencil unit=USD
    claimed: value=1830, denom=mn, unit=USD

(use fiscal calendar to match period labels to actual dates in chunk),
check denom against chunk headers, check unit. Then call submit_verdicts
with your verdict for ALL cells.
```

**No sibling chunks.** The ±1k overlap baked into each chunk
by ingest already provides neighboring context. Sending full
adjacent chunks is redundant and inflates Validator token cost.

The Validator checks:
1. **Literal match**: value appears in chunk text?
2. **Correctness**: right period? right timeframe?
3. **Denom**: Leng claimed `denom: "mn"` — chunk header says
   `"($ in millions)"` → confirmed. If Leng said `"k"` but
   chunk says `"(in millions)"` → Validator corrects denom.
4. **Unit**: Leng claimed `unit: "USD"` — chunk context shows
   `"$"` → confirmed. Mismatch → Validator rejects.
5. Uses overlap context for column headers, section context.

### Concurrency and first-write-wins

Multiple Validators can race for the same cell_id:
- Same file, different chunks (N Lengs hit the same cell)
- Different files (BP assigned same cell to multiple files)

All Validators run in parallel. `submit_verdicts` handler uses
a single `threading.Lock` per job stencil. Compare-and-swap
per cell: if `values[cell_id]` is None, write; if already
filled, "skipped: already filled". Both are normal outcomes.

Non-deterministic: whichever Validator gets the lock first wins.
Acceptable for demo — all validated values should be correct.

## Phase 2: Merge + Compute

Python. No LLM. Runs after all Dispatchers complete.

**Job stencils are ephemeral.** They exist only as in-memory
dicts during Phase 1 (parallel containers for per-firm
extraction). After Phase 2 merges their values into the work
stencil, they are discarded — not persisted to disk.

**Work stencil is the auditable artifact.** Contains ALL firms'
rows including helper rows (Revenue, GP, D&A, etc.) that
analysts need to verify the math. Persisted to disk after
Phase 2 fills it.

**Ans stencil is the user-facing output.** Contains only
ans-marked rows. Populated from work stencil after formulas
are computed. Persisted to disk.

```
Phase 2 flow:
  Step 1: Merge job stencil values → work stencil
          (copy values + sources from each firm's job dict
           into the work stencil's global row space)
  Step 2: Compute formula cells on work stencil
          (ascending row order = topo order, same as before)
  Step 3: Extract ans rows from work stencil → ans stencil
  Step 4: Serialize ans rows → display stencils (downstream)

  Persist: work_stencil.json (audit), ans_stencil.json (output)
  Discard: job stencil dicts (ephemeral, in-memory only)
```

```python
# stencil_safe_math.py
import ast
import operator

SAFE_OPS = {
    ast.Add: operator.add,
    ast.Sub: operator.sub,
    ast.Mult: operator.mul,
    ast.Div: operator.truediv,
}

def _safe_math_eval(expr: str) -> float:
    """Evaluate arithmetic expression. Only +, -, *, / allowed.

    Wraps SyntaxError → ValueError so callers catch one type.
    """
    try:
        tree = ast.parse(expr, mode="eval")
    except SyntaxError as e:
        raise ValueError(f"Unparseable expression: {expr}") from e
    return _eval_node(tree.body)

def _eval_node(node):
    if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)):
        return node.value
    if isinstance(node, ast.BinOp) and type(node.op) in SAFE_OPS:
        left = _eval_node(node.left)
        right = _eval_node(node.right)
        return SAFE_OPS[type(node.op)](left, right)
    if isinstance(node, ast.UnaryOp) and isinstance(node.op, ast.USub):
        return -_eval_node(node.operand)
    raise ValueError(f"Unsafe expression node: {ast.dump(node)}")
```

```python
def _compute_formula_cells(work_stencil: dict, channel=None) -> None:

    Cross-firm formulas impossible — Rn refs are within-firm
    (guaranteed by topo sort). Row 5 (LITE GM = R2/R1) and
    row 11 (INNO GM = R8/R7) both work correctly because
    row numbers are global and disjoint.

    Divergence check: when Leng found a compute cell directly
    AND all feeder rows are also filled, compute the formula
    anyway and compare. If divergence > _DIVERGENCE_THRESHOLD,
    print a warning to CLI. Leng-direct value still wins —
    warning is for analyst review, not correction. Known risk:
    denom miss on ratio (e.g. "32.8" stored as 32.8 instead
    of 0.328) produces ~100x divergence warning but no auto-fix.
    Analyst catches it from the ⚠ output.
    """
    rows = work_stencil["rows"]
    values = work_stencil["values"]
    col_letters = work_stencil["col_letters"]

    for row_num, row in sorted(rows.items(), key=lambda x: int(x[0])):
        if row.get("type") != "compute":
            continue
        formula_template = row.get("formula", "")

        for col in col_letters:
            cell_id = f"{col}{row_num}"
            leng_direct = values.get(cell_id)

            # Try computing from formula regardless
            expr = formula_template
            can_compute = True
            col_idx = col_letters.index(col)

            # Regex-based substitution: each Rn / Rn[±k] match
            # resolved independently. No ordering concerns —
            # re.sub handles R10 vs R1, R1[-1] vs R1 atomically.
            def _resolve_ref(m):
                nonlocal can_compute
                rn = m.group(1)
                offset_str = m.group(2)  # e.g. "[-1]", "[+2]", or None
                if offset_str:
                    offset = int(offset_str.strip("[]"))
                    target_idx = col_idx + offset
                    if target_idx < 0 or target_idx >= len(col_letters):
                        can_compute = False
                        return "0"  # placeholder, won't be used
                    ref_cell = f"{col_letters[target_idx]}{rn}"
                else:
                    ref_cell = f"{col}{rn}"
                ref_val = values.get(ref_cell)
                if ref_val is None:
                    can_compute = False
                    return "0"
                return str(ref_val)

            expr = re.sub(
                r"R(\d+)(\[[+-]?\d+\])?", _resolve_ref, formula_template
            )

            computed = None
            if can_compute:
                try:
                    computed = _safe_math_eval(expr)
                except ZeroDivisionError:
                    # Divisor = 0 almost certainly means Leng misread
                    # a value. Warn analyst, leave cell null.
                    metric = row.get("metric", "?")
                    firm = row.get("firm", "?")
                    msg = (
                        f"⚠ {cell_id} ({metric} {firm}): "
                        f"division by zero in {formula_template} "
                        f"— likely bad extraction upstream"
                    )
                    if channel:
                        channel.print(msg)
                    else:
                        print(msg)
                except ValueError:
                    pass

            if leng_direct is not None:
                # Leng-direct wins. But check divergence if
                # formula is also computable.
                if computed is not None and leng_direct != 0:
                    pct_diff = abs(computed - leng_direct) / abs(leng_direct)
                    if pct_diff > _DIVERGENCE_THRESHOLD:
                        metric = row.get("metric", "?")
                        firm = row.get("firm", "?")
                        msg = (
                            f"⚠ {cell_id} ({metric} {firm}): "
                            f"Leng-direct={leng_direct}, "
                            f"formula {formula_template}={computed}, "
                            f"divergence={pct_diff:.0%}"
                        )
                        if channel:
                            channel.print(msg)
                        else:
                            print(msg)
                continue  # Leng-direct wins either way

            if computed is not None:
                values[cell_id] = computed
                work_stencil["sources"][cell_id] = f"formula:{formula_template}"
```

### Step 3: Fill ans stencil from work stencil

```python
def _fill_ans_stencil(
    work_stencil: dict, ans_stencil: dict,
) -> dict:
    """Extract ans-marked values from work stencil into ans stencil.

    Work stencil has all rows (helpers + ans) with filled values.
    Ans stencil gets only ans-marked rows' values.
    Uses work stencil cell IDs directly — no ID translation.
    """
    row_mapping = ans_stencil["row_mapping"]  # {firm: {metric: row_num}}
    col_letters = ans_stencil["col_letters"]

    for firm, firm_rows in row_mapping.items():
        ans_stencil["filled"][firm] = {}
        for metric, row_num in firm_rows.items():
            for col in col_letters:
                cell_id = f"{col}{row_num}"
                ans_stencil["filled"][firm][cell_id] = (
                    work_stencil["values"].get(cell_id)
                )

    return ans_stencil
```

### Step 4: Serialize + persist

Convert work stencil's ans rows into display stencil format
for downstream consumption (PTECA, stencil2chart). Persist

implemented at M3a (not M5) because `_exec_pms2` needs

```python
def _serialize_to_display_stencils(
    work_stencil: dict,
) -> list[dict]:
    """Extract per-firm display stencils from work stencil.

    Only ans-marked rows included. Metric names are plain
    (no firm prefix). Downstream knows firm from 'firm' field.
    """
    firms = work_stencil["firms"]
    display_stencils = []

    for firm in firms:
        rows_out = []
        for row_num, row in sorted(
            work_stencil["rows"].items(),
            key=lambda x: int(x[0]),
        ):
            if row["firm"] != firm or not row.get("ans"):
                continue
            values_list = []
            for col in work_stencil["col_letters"]:
                cell_id = f"{col}{row_num}"
                values_list.append(work_stencil["values"].get(cell_id))
            rows_out.append({
                "metric": row["metric"],
                "values": values_list,
                "unit": row.get("unit", ""),
            })
        display_stencils.append({
            "firm": firm,
            "periods": work_stencil["periods"],
            "rows": rows_out,
        })

    return display_stencils


def _persist_phase2(
```

## Startup staleness check

On PSOAS startup (`psoas.py`), before entering the REPL.
Uses `register("Chunk_master")` for prompts (TerminalRouter's
daemon thread is already running at module import):

1. **Missing docstore**: if `data/index/docstore.json` does not
   exist:
   ```

   ```
   User `y` → call `00_Ingest.main(config)` then
   `01_Chunk.main(config)` (function calls, same process,
   blocking), then continue to REPL. Both scripts expose a
   `main(config)` entry point for this.
   All paths (`pms2_raw_dir`, `pms2_data_dir`, `pms2_index_dir`)
   come from Config — no standalone hardcoded paths in scripts.
   User `n` →
   ```
   [Chunk_master] tis a waste of tokens u know
   ```
   then launch PSOAS REPL anyway (PMS1/PTECA work,
   `run_pms2` fails at call time with "no docstore").
   User `exit` → terminate program.
2. **Staleness**: compare newest mtime across three stages:
   - `data/files_raw/` (recursively)
   - `data/files_ingested/` (recursively, excluding `.json` metadata)
   - `data/index/docstore.json`

   If `files_raw/` is newer than `files_ingested/`, or
   `files_ingested/` is newer than `docstore.json` → prompt:

   ```
   [Chunk_master] Files ingested on 2026-07-20. Raws modified on 2026-07-22. Reingest? [y/n]
   ```

   User `y` → call `00_Ingest.main(config)` then
   `01_Chunk.main(config)` (function calls, same process,
   blocking), then continue to REPL.
   User `n` → continue with stale docstore.

   Both scripts always run together as one unit. No partial
   re-ingest (ingest without re-chunk).

   **Script entry points**: each script is both importable and
   runnable standalone. `if __name__ == "__main__"` calls
   `main(Config.from_env())`. `psoas.py` imports and calls
   `main(config)` directly — same process, shared Config.

## System prompt files — DEFERRED

Per Spec 16 (Externalize System Prompts), all PMS2 system
prompts live in `sysprompts/pms2_{role}/{profile}.md` and are
loaded via `load_sysprompt()`. Template vars resolved at load
time, hard crash on missing file or unresolved vars.

**Prompt authoring is deferred to the final implementation
step.** Minimal stub `.md` files created from the start so
`load_sysprompt()` is wired from day one. Real prompt content
designed collaboratively later (user reviews every prompt
before commit). Tendency to hardcode behavioral assumptions
in prompts is a known failure mode — prompts are written last,
reviewed first.

Five prompt roles:

```

```

### Cross-cutting: timeframe strictness

**All agents that touch data (Sekei, BP, Leng, Validator) need
explicit sysprompt language on timeframe matching.** This is the
#1 source of silent wrong answers.

- `quarterly` = that quarter ONLY. Not annual. Not YTD. Not LTM.
- `annual` = full fiscal year. Not a single quarter.
- `LTM` = trailing 12 months. Not annual. Not quarterly.
- 10Q filings contain BOTH quarterly and YTD figures in the
  same table. Leng must pick the right one.
- Annual figures in quarterly filings are NOT quarterly figures.

Per-agent enforcement:
- **Sekei**: set `timeframe` correctly per row.
- **BP**: no filing-type assumptions (data is heterogeneous —
  analyst notes, earnings decks, Chinese filings, not just
  SEC 10K/10Q). Route by filename heuristics only.
- **Leng**: cell description includes timeframe. Extract only
  figures matching that timeframe. `found=false` if only
  wrong-timeframe figures present. Do not assume document
  type — any file can contain any timeframe.
- **Validator**: reject if extracted value's period context
  doesn't match cell's timeframe (e.g. annual fig claimed
  as quarterly).

### Key content notes (intent only — NOT final prompt text)

**Sekei**: firm resolution, metric disambiguation, **reporting
currency confirmation per firm**, stencil building. Proposes
helper rows + formulas from financial domain knowledge. Outputs
firm-specific rows with plain metric names (e.g. `"Revenue"`,
`"D&A"` — NOT firm-prefixed). Each row has a `firm` field.
Same KPI scaffold duplicated per firm with per-firm `unit`.
Formulas use `{ExactMetricName}` syntax (plain names, same
formula string reused across firms — scoped by `firm` field).
Does NOT assign row numbers or cell IDs. Proposes reporting
currency per firm from domain knowledge (US → USD, China → CNY),
confirms with user. Template vars: `{{query}}`, `{{firms}}`, `{{periods}}`,
`{{top_level_dirs}}`, `{{valid_units}}` (canonical units from
units.json — Sekei picks from these when assigning row units).
`{{periods}}` = expanded periods from `_expand_periods()`
(e.g. `["Q1FY2025","Q2FY2025","Q3FY2025","Q4FY2025"]` or
`["FY2025","FY2026","FY2027"]`). Sekei uses these directly
in finalize_stencil — does not re-derive or confirm them.

**Mapper**: dir navigation, fuzzy firm matching. Template vars:
`{{firm}}`, `{{query}}`.

**Batch Planner**: file routing reasoning. Receives current job
stencil state (showing nulls), searched_files history, file
inventory. Can duplicate cells across file entries when unsure.
Can ask_user to pitch tentative plan BEFORE calling
run_leng_caller. Called fresh each Dispatcher iteration — no
persistent memory, but gets structured state.
**Critical**: BP has never read file contents. It only sees
filenames, filetypes, sizes, and searched_files outcomes.
Must never claim what a file contains — only speculate from
filename metadata.
Template vars: `{{firm}}`, `{{job_stencil}}`,
`{{file_inventory}}`, `{{searched_files}}`,
`{{active_cells}}`, `{{iteration}}`.

**Leng**: type-agnostic extraction, no tools, single call.
**Receives firm name** — only extract values for that firm.
Critical for sector/thematic files (e.g. `0 Optical/` PDFs)
that mention multiple firms in the same chunk.
Per cell: report value, denom, and unit. Extract number
as-written (do NOT scale). Detect denomination from chunk
context (e.g. `"$ in millions"` → `denom: "mn"`). Detect
unit from chunk context (e.g. `"$"` → `unit: "USD"`,
`"%"` → `unit: "float"`). Anti-hallucination: found=false
if unsure. Template vars: `{{firm}}`, `{{valid_denoms}}`,
`{{valid_units}}`, `{{fiscal_calendar}}` (if available —
absent for annual or resolver failure. When present, use
it to match period labels like "Q1FY2025" to actual calendar
dates like "Jul 1 2024 – Sep 30 2024" in the source text.
E.g. source says "ended Sep 30, 2024" → matches Q1FY2025
per fiscal calendar. Without calendar, fall back to best
guess from period label alone).
**Cross-lingual note**: some source files are Chinese-language
(e.g. Innolight filings — 营业收入 = Revenue, 毛利润 = Gross
Profit). Cell descriptions use English metric names. Leng
sysprompt must instruct: match English metric names against
Chinese equivalents in chunk text. Haiku handles this natively
— no translation step needed, just an explicit instruction
so it doesn't skip non-English content.

**Validator**: per-cell verification agent loop. No ask_user —
resolves ambiguity by reasoning or rejects. Checks literal
match, period/timeframe correctness (use `{{fiscal_calendar}}`
if present to cross-check period labels against actual dates
in chunk — e.g. confirm "ended Sep 30, 2024" matches
Q1FY2025 per calendar), denom correctness (cross-check
Leng's claimed denom against chunk header), and unit
correctness (cross-check against chunk context).
Single terminal tool: `submit_verdicts` (batch — handles
both writes and rejections).
Template vars: `{{valid_denoms}}`, `{{valid_units}}`,
`{{fiscal_calendar}}` (same calendar as Leng — if present).
- `{{valid_denoms}}` = canonical denom set from
  `DENOM_FACTORS` keys: `["units","k","mn","bn","tn","%","bps"]`.
  Validator normalizes Leng's non-canonical denom strings
  (e.g. `"millions"` → `"mn"`, `"M"` → `"mn"`) before
  calling `submit_verdicts`. Without this, handler rejects
  on unknown denom and BP wastes a retry loop.
- `{{valid_units}}` = canonical unit set from `units.json`:
  `["USD","JPY","EUR","GBP","CNY","float"]`.
  Validator normalizes non-canonical unit strings
  (e.g. `"$"` → `"USD"`, `"dollars"` → `"USD"`,
  `"RMB"` → `"CNY"`) before calling `submit_verdicts`.
  Python `_UNIT_ALIASES` is a safety net, not a substitute
  — Validator doing it first is cheaper than a rejection +
  retry cycle.
Both lists are static (read from hardcode_dependencies at
load time). ~30 tokens added to sysprompt. Negligible cost.

| `MapperBatch_{firm}.md` | Mapper LLM calls (dir navigation) for that firm. | `sekei_loop.py` (run_mapper handler): per-firm trace via `with_trace()`, flush after mapper returns |

Iter 0 also contains FiscalCalResolver call (pre-loop, same trace). | `dispatcher.py`: set BEFORE pre-loop (covers fiscal cal + iter 0). Flush + new trace at start of each subsequent iteration. |
| `LengValidator_{firm}_iter{N}.md` | All Leng LLM calls + all Validator LLM calls for that firm's iteration N. Interleaved chronologically. | `leng_caller.py`: own trace per invocation |

Rationale: one trace file per Dispatcher iteration keeps each
iteration's LLM calls isolated. When debugging "why wasn't
GP FY27 found?", you look at the iteration where that cell was
active, not a monolithic log.

## Orchestrator sysprompt update

Orchestrator is the friction layer. It must resolve all
`run_pms2` params with the user BEFORE calling the tool.
Sekei trusts these inputs — no re-confirmation.

**Orchestrator must clarify with user before calling `run_pms2`:**

1. **firms** — which companies. Resolve ambiguity ("optical
   names" → specific tickers). Do not guess.
2. **periods** — which fiscal years. "last 3 years" →
   `["FY2024","FY2025","FY2026"]`. Confirm if ambiguous.
3. **granularity** — `annual` / `quarterly` / `half`.
   Ask if not obvious from query. "quarterly results" →
   `quarterly`. "FY2025 revenue" → `annual` (default).
4. **query** — what metrics. Pass through as-is. Metric
   disambiguation (GM = GP/Rev?) is Sekei's job, not
   orchestrator's.

**One granularity per call.** Mixed-granularity queries
(e.g. "LITE quarterly, Innolight annual") require orchestrator
to split into two `run_pms2` calls.

**Orchestrator asks_user to confirm before calling `run_pms2`.**
This is the natural friction point — one ask_user with all
params laid out, user confirms or corrects. Example:

```
[ORCHESTRATOR] PMS2 extraction:
  Firms: LITE, Innolight
  Periods: FY2025, FY2026, FY2027
  Granularity: annual
  Metrics: Revenue, Gross Margin, EBITDA
  Confirm? [y / edit]
> y
```

After confirmation, orchestrator calls `run_pms2` with
structured params. Sekei receives them as ground truth.

**Orchestrator sysprompt key lines (intent, not final text):**
- "Before calling run_pms2, always confirm firms, periods,
  and granularity with the user via ask_user."
- "Default granularity is annual unless user specifies
  quarterly/half."
- "Do not call run_pms2 until user confirms the extraction
  parameters."
- "Metric clarification is NOT your job — pass query as-is.
  PMS2 Sekei handles disambiguation internally."
